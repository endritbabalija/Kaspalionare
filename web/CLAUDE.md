# web/: the Kaspalionare page (front end, testnet-10 beta)

Spec: `docs/specs/frontend.md`. Build log and stage notes: `docs/specs/frontend-handoff.md`. Root rules: `../CLAUDE.md` (Safety, no keys, testnet-10 and simnet only).

## Rules the page keeps

- **No lottery logic in TypeScript** (spec 1). Every figure is decoded from chain state by the wasm (`crates/web`) or computed by it (`jackpotOdds`, builders' `BuiltTx`). `src/lib/format.ts` only prints decimal strings (KAS 2 decimals, exact sompi, DAA at 10/s as a clock).
- **No hand-written mirror of a Rust type** (spec 1.1). Types come from the generated `src/wasm/<dev|release>/web.d.ts` (`import type { … } from '@wasm/web.js'`). The worker's call list (`src/worker/protocol.ts` `CALLS`) holds export names only; argument and result types are `Parameters<>`/`ReturnType<>` of the generated functions.
- **Nothing from the indexer is trusted** (spec 6.3). Read a response with `fetchText` under its cap (`indexerLimits`), parse it with the worker's `parseIndexer*` (never `JSON.parse`; ESLint refuses it in `src/`), read every entry from the node by outpoint (`nodeEntries`, `nodeCoins`; never the indexer's), then `checkIndexer*`. X's header comes from the node (`nodeAnchorBlock`), never the indexer.
- **Errors are typed codes, one message each** (spec 1.1 AX): the Rust table (`lottery::web::Code`), loaded at boot (`errorTable`). The page raises codes of the same table (`indexer_unavailable`, `worker_stopped`, `bytes_length`) through `PageError` (`src/lib/errors.ts`). Show `message`; `detail` is for logs.
- **Copy rule** (spec 5 rule 6, D137): no taglines, helper text or secondary labels. Figures and their names, status, errors, the network badge and control labels only. Explanations live on How it works (S6).
- **AX**: every interactive element has a stable `data-testid` and an accessible name (the e2e `namedAndTagged` check); each component in its own small file under `src/components/` with every state of spec 4; touch targets at least 44 px; meaning never by colour alone.
- **Tokens in one file**: `src/theme/tokens.css` (both themes, spec 5's table exactly; `tokens.test.ts` pins the values and checks WCAG AA contrast of every text pair). Tailwind utilities map to them in `src/index.css` (`bg-ground`, `text-ink`, `border-rule`, …). Never a raw colour in a component.
- **Dev only**: the component catalogue (`#/dev/catalogue`, `src/dev/Catalogue.tsx`), the dev faucet (`src/dev/faucet.ts`, `DevFaucet.tsx`) and the e2e hooks (`src/dev/hooks.ts`, `window.__klDev`: hold a signed purchase before sending, force the shard) are imported behind `import.meta.env.DEV`; `scripts/check-bundle.mjs` fails the production build if any trace of them, or of the simnet configuration, is in `dist/`, and checks the served wasm (the release package, no fixture code or key). Its markers are used at run time so they survive in a dev build: `scripts/check-bundle-control.mjs` (run by `npm run build`) builds in development mode and requires every one (the negative control). The simnet dev faucet answers only the dev page's origin.
- **Purchase rules** (F2/F3 review): Buy signs exactly what the cost panel shows. After a shard conflict a rebuild is signed by itself only when round, combinations, payout, price, deposit and its date, referral, fee and total are unchanged (`sameAsShown`); otherwise the new figures wait for a press (`purchase_changed`); a round that stopped selling is `sales_closed` (never a ticket of the next round). A submit whose answer is lost is settled from the chain (`settleSubmit`: the same signed transaction again, or its ticket output live) and shown as Checking, never as a plain failure; `submit_unknown` keeps Buy disabled. The cost panel's top-level rows (Price, Deposit, Network fee) add up to Total; Referral and the deposit's Back date are `part` rows. Status and "selling" come from chain objects only, never the indexer's status field.
- **Game shape from the wasm**: `gameShape()` (5 of 1..30, B_MAX, F_MAX); no TypeScript copy of game sizes.
- **Wallets** (spec 6.2, F3 part B): adapters behind one interface (`src/wallet/types.ts`): KasWare (always the explicit `signInputs` index list, never `pushPskt`, `kaspa_testnet_10` only), Kaspire (UNTESTED; the network checked again before each signature, as KasWare), the quick wallet (key in its own IndexedDB database, never in the store or its backup; written only by compare-and-swap, so a stored key is replaced only after the sheet showed it (Import, then Replace); the adapter is pinned to the key it connected with and signs nothing if the stored key changed: `wallet_changed`; absent from a mainnet check build: `src/wallet/quickEnabled.ts`, `npm run check:mainnet`). A wallet request that never settles ends in `wallet_timeout` after 5 minutes (`Serial`). Coins always come from the node (`nodeCoins`), one wallet request at a time (`Serial`), and every wallet answer goes through `assemble` (the post-sign check) before `nodeSubmit` (`signAndSubmit` in `src/play/buyFlow.ts`). A transaction ID the node refused as a conflict is never signed or sent again (`refusedLately`, 10 minutes); claims, returns, vault actions and caller transitions build again instead (`unrefused` in `src/tickets/send.ts`: a pause, up to 5 builds, else `node_conflict`), a purchase moves to another shard (F6 part A review N1).
- **Local store** `webstore/2` (spec 6.3; F4): the record types and the database layout come from `crates/web/src/webstore.rs` (`webstoreInfo`); `src/store/`. A `webstore/1` store (F3) is migrated in place (`info.reads`; the records read unchanged, the `pending` store is added). A round copy is kept only after `checkIndexerRound` checked every list, and only through `mergeCopy` (Rust; F4 review): never a stage back (open → closed with the marker → drawn with the round result), never fewer pools, the closed copy's marker kept into the drawn copy (with it, every pool the draw created is listed). A purchase whose outcome is unknown is kept as `pending` (signed), a claim or return as its ticket's `pending`; both are settled on the next visit and sent again by themselves only within `RESEND_MS` (10 minutes) of the signature; an older purchase waits for a press (Pending purchase, Send).
- **Claims and deposit returns** (F4, `src/tickets/`): built from the ticket's node entry, the round's live pools found on a node by script (`nodeScriptEntries`, from the copy's round result) and the copy's lists, so they need no indexer API; every row's figure from `ticketCard`/`claimFigures`/`returnFigures` (bound to the built transaction); sent through `signAndSubmit` (post-sign check) and "accepted" when any of its own outputs is live on the node (the successor, the payout or the change; never the pool's successor alone). One claim or return at a time. A copy that no longer rebuilds the chain's roots (`checkCopy`: `copy_mismatch`) builds nothing. A win is "Expired" only for a listed pool the chain shows absorbed; a winning tier whose pool the copy does not show is "Unknown" (the round is copied again). Return deposit is offered only when nothing unclaimed can still be claimed. J3 keeps only tickets paying the connected wallet; a ticket paying elsewhere shows its Payout row. "Void" only as far as the chain supports it (`voidSupported`, and not against the copy).
- **Rounds and Run the round** (F5, `src/rounds/`, S3, S4): a round's status and figures only from node-checked objects (`checkIndexerRound`'s `facts`: T, S, J, D, the void lock, the claim deadline, the roots, the pools, the caller reward, R; each with the outpoints it is read from); a figure only the indexer states says "Unverified"; numbers "Final" from a live pool, "Provisional" before the draw (bound to the node's anchor block), never verified. Verify in this browser is `verifyRound` (Rust; each check its own match / mismatch / not checkable); X.hash after the draw is shown checked only when bound to a public node's block (`anchorBound`). S4: due times from the facts, compared with the node's virtual DAA; close/draw/void built from the live checked objects, the draw's purchases and the indexer's anchor proof only after `checkIndexerRound` checked them (roots; proof bound to the node's block and D); the rows from `callerFigures` (bound to the built transaction); sent through `sendAndWait` (post-sign check, accepted on a wallet output); `submit_unknown` keeps the press disabled while the same transition is due. F5 review: a draw or void absorbs the expired pools of earlier rounds (design 7.3): the indexer's `GET /v1/pools` only says where to look, each pool is read from the node by outpoint and `absorbablePools` (Rust) keeps those past their claim deadline (for a draw also below the void lock), oldest first, at most A_MAX; without the list nothing is absorbed. A void takes no purchases. An indexer answer for another round than the one asked for is `chain_mismatch` (`net/indexer.ts`). m is checked only with `mChecked` (a marker, pool, open controller or shard; a settlement record alone fixes no status), the close and draw transaction IDs only with `facts.closeTx`/`facts.drawTx` (the marker or next controller; the next drawer), X before the draw is "Provisional", after it checked only when bound to a node's block (the detail binds it itself). A caller build is shown and signed only for the (round, transition, wallet, live objects) it was made for (`useRoundDetail`). Verify items' `detail` is never shown (`data-code` only).
- **Vault** (F6 part A, S5, `src/vault/`, `screens/Vault.tsx`, `screens/vault/useVault.ts`): the vault, the wallet's positions and requests and the records they settle against from `GET /v1/vault`, `/v1/positions?owner=`, `/v1/requests?owner=`, each object read from the node by outpoint (spent ones left out) and checked (`checkIndexerObjects`), then every figure from `vaultView` (Rust: price, L, pending totals, worth today, wmin and the W4b range, the request age, each settlement's mode and amounts); a position or request of another owner is never shown as the wallet's (`foreign`). Deposits only for the wallet's own (Schnorr) address; a withdrawal's shares from `withdrawChoice` (`vault_amount` for any the vault does not take; code 55; the Part range's Least and Most are amounts it takes, `leastShown`/`mostShown`, printed exactly with `kasExact` so that typed back each is taken: F6 part A review S1), its owner input a wallet coin at the position owner's address. Each action's rows from `depositFigures`/`withdrawFigures`/`settleFigures` (bound to the built transaction, terms as rows: Revocable, Price, Refund); built per key (action, amount, wallet, live objects; rebuilt after every press), sent through `sendAndWait` (post-sign check), accepted on its own outputs; `submit_unknown` keeps that press disabled while the same objects are live; one action at a time. No pending record is kept (as F5's caller transitions).
- **Backup** (F4, S8, `src/store/backup.ts`): written and read in Rust (`backupWrite`, `backupRead`: size cap, strict format, this instance, checksum, every record; `backup_invalid`), then every record checked against the chain before anything is kept (`backup_mismatch` refuses the whole file). Never the quick wallet's key; pending purchases and claims are not exported. The writer keeps the file within what the page reads (`indexerLimits().backup`, and the worker's argument cap once escaped) and leaves out, by name, any record failing its own check. Node reads go in batches of `indexerLimits().nodeObjects` (`nodeEntries` in `tickets/load.ts`).
- **How it works** (F6 part B, S6, D138; `screens/HowItWorks.tsx`): the one page with explanations. Every number of its example round comes from `src/screens/how/cabinet-model.json`, written by the Rust lottery code (`crates/lottery/tests/f6_figure.rs`, `figure_model_is_current` checks it; `-- --ignored write_figure_model` rewrites it); the page only prints it. The draw-cabinet figure is its own file, `public/figures/draw-cabinet-tour{,-light}.html`, built by `node ../docs/figures/draw-cabinet/build.mjs --all` (the kit in `tools/anatomy-kit/`, no npm) from that model, in the page's tokens (`docs/figures/draw-cabinet/embed.css`); shown by `FigureFrame` in an iframe sandboxed to `allow-scripts` (opaque origin: no access to this page, its storage or the quick wallet's key), only when S6 opens, sized by the figure's one `postMessage` (`figureHeight`: from that frame only, bounded). `src/screens/how/figure.test.ts` checks the chain: the figure built from the current model, its inline script and styles hashed in vercel.json's figure CSP, the two header rules disjoint, embed.css's colours equal to the tokens. Generated, so Prettier skips them.
- **npm safety**: run every npm/npx command with `web/` as the working directory (it has its own `package.json`; `C:\Users\endri\package.json` exists, so npm run elsewhere lands in the home folder). Never install globally. Playwright's browsers go to `web/.playwright-browsers`.
- Low-memory PC: never run a cargo build and a Vite build at once.

## Layout

- `src/main.tsx` entry; `src/app/` shell (`Shell.tsx`: header, network badge, menu, bottom nav), hash routes (`routes.ts`), session (`ctx.ts`).
- `src/worker/`: `lottery.worker.ts` (the wasm in a Web Worker), `protocol.ts` (typed messages), `client.ts` (`LotteryClient`: size cap, restart on a crash, replays `boot`), `session.ts` (boot: `errorTable`, `start(network)`, `nodeConnect(url)`).
- `src/net/`: `fetchText.ts` (capped reads), `indexer.ts` (API client), `round.ts` (a round checked against the node; the round card's figures).
- `src/components/`: Round row, Verify panel, Caller panel (F5), Number ball, Bonus tile, Round status pill, Jackpot and countdown, Amount, Time, Hash or address, Transaction progress, Cost panel, Ball row, Figure row, Claim row, Ticket card, Local-copy box, Pending purchase (F4; states in `ticketStates.ts`); `ui/` the shadcn/ui primitives (Button, DropdownMenu over Radix) restyled with the tokens.
- `src/screens/`: Play (S1: round card, picker, ticket, cost panel from `buyFigures`, buy, progress; `play/`), My tickets (S2, F4: ticket cards, claim rows, return deposit, the local-copy box; `tickets/useTickets.ts`), Backup (S8, F4), Wallet (S7; `wallet/QuickWalletPanel.tsx` lazy), Vault (S5), How it works (S6; `how/` its model and tests; components Figure frame, Money split). `src/tickets/` (F4: `load.ts` the store brought up to date and the cards, J3 by payout, pending purchases; `claimFlow.ts`, `send.ts`). `src/play/` (picker state, the purchase flow), `src/wallet/` (adapters, session, quick wallet), `src/store/` (IndexedDB, `webstore/2`, the round copy, the backup), `src/referral/` (`?ref=`, spec 7), `src/test/` (the in-process wasm worker and fixtures for unit tests).
- `src/theme/`: tokens, fonts (Geist, Geist Mono: vendored woff2 in `src/fonts/`, OFL 1.1), the theme switch (dark for a first-time visitor whatever the device says; the menu's dark / light / device, remembered: `kl.theme`; owner decision 2026-10-26 amending D139; `public/theme-boot.js` sets it before first paint).
- `scripts/`: `wasm.mjs` (build `crates/web` and run wasm-bindgen), `dev-simnet.mjs` (the one-command dev run), `check-bundle.mjs`, `ensure-wasm.mjs`, `playwright-install.mjs`.
- `src/vault/` (F6 part A: `load.ts`, `flow.ts`), components Vault figures, Vault position card, Deposit panel, Withdraw panel, Settle rows, Vault terms; `src/rounds/` (F5: `load.ts` the list rows and the round detail checked against the node, `verify.ts`, `caller.ts` the S4 flow); `src/screens/Rounds.tsx` and `screens/rounds/` (list, detail, hooks); components Round row, Verify panel, Caller panel, Source link, Unverified.
- `e2e/`: Playwright against the simnet dev run (`rounds.spec.ts`, F5: the list and Verify, draw and close from the S4 panel, the doctored API through `indexer-api-doctored` on the dev run's store (one per mode, the page's indexer requests routed to it in the browser); `void.spec.ts`, F5, **on request only** (owner, DECISIONS 2026-10-27): `npm run e2e:void` (sets `E2E_VOID=1`; a plain `npm run e2e` skips it), after `npm run e2e` in the same dev run, and always before committing a change to draws, voids or the rounds pages: a void from the panel after the TEST-ONLY `POST /mine?to=void` (864,000 blocks: about half an hour, and the dev node is left slow and large, about 6.6 GB of memory, so nothing runs after it); `vault.spec.ts`, F6 part A: deposit request, settle (convert), a part withdrawn and a second deposit, the page's own draw converting both (posting the record), both settled (the last drains the record back to this wallet), after the TEST-ONLY `POST /close` and `POST /mine?to=vault` (past the vault's VAULT_REQ_DELAY); refund mode is not reachable on a simnet (Rust and Vitest cover it); `tickets.spec.ts`, F4: uses the dev faucet's TEST-ONLY `POST /round` to draw deterministically and `POST /close` to leave a round closing; the indexer API is "stopped" by refusing every request to it in the browser context, or "hanging" by never answering).

## Commands (from `web/`)

- First time: `npm ci`, then `npm run e2e:install` (Chromium into `web/.playwright-browsers`). Rust side as `../CLAUDE.md` (the wasm32 target, LLVM clang/ar, `wasm-bindgen-cli` 0.2.100; simnet needs LIBCLANG_PATH and protoc).
- **Dev run against the private simnet (one command):** `npm run dev:simnet`. Builds the dev wasm (`crates/web` features `simnet,node`) and `simnet` (release; about 10 minutes the first time), starts `simnet dev` (a fresh private node, round 1 drawn, round 2 closing, round 3 open, the indexer API on 127.0.0.1:8790, the node's Borsh wRPC on 127.0.0.1:18610, the dev faucet on 127.0.0.1:8791), waits for its `crates/target/simnet-dev/current.json`, then serves the page on http://127.0.0.1:5173/. `--skip-build` reuses the built binaries. Ctrl-C stops everything.
- Tests: `npm test` = typecheck (`tsc -b`, strict) + ESLint + Prettier check + Vitest (builds `src/wasm/dev` first if it is missing; the post-sign attack tests load it in-process through the worker's handler). Single parts: `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run test:unit`.
- Void end to end, on request: `npm run e2e:void` (only `e2e/void.spec.ts`, E2E_VOID=1; about 35 minutes; run it after `npm run e2e` in the same dev run before committing any change to draws, voids or S3/S4).
- End to end: `npm run e2e` (reuses a running `npm run dev:simnet`, else starts one; skips the void test; F5's doctored test needs `crates/target/release/indexer-api-doctored.exe`: `cargo build -j 4 -p indexer-api --features doctored --release --bin indexer-api-doctored`; the void test mines about 864,000 blocks, about 2.5 GB in `crates/target/simnet-data/`). Screenshots in `test-results/shots/`. The dev faucet pays 100 KAS a request (at most 200 a run), combining the dev wallet's coins (the dev loop's mined coins included); a full suite funds 8 quick wallets.
- wasm packages: `npm run wasm:dev` (simnet,node → `src/wasm/dev`), `npm run wasm:release` (node → `src/wasm/release`, then `wasm-opt -Oz`; the release artifact is the documented `crates/web` wasm build plus `--features node`, so W4 checks it), `npm run wasm:mainnet` (TEST-ONLY mainnet,node → `src/wasm/mainnet`, for `check:mainnet`).
- Production build: `npm run build` (release wasm, typecheck, `vite build`, `check-bundle.mjs`). Testnet-10 only: it refuses `VITE_NETWORK` other than testnet-10 and any `VITE_FAUCET_URL`. Configuration (spec 6.5, `src/config.ts`): `VITE_INDEXER_URL`, `VITE_COVENANT_ID`, optional `VITE_NODE_URL` (else the public resolver), `VITE_BUNDLE_HASH`, `VITE_REFERRAL_ADDRESS` (kaspatest:; the dev run passes a kaspasim: one), `VITE_EXPLORER_URL`, `VITE_EXPLORER_URL` (https only), `VITE_FAUCET_LINK` (https; default `https://faucet-tn10.kaspanet.io`, owner 2026-10-26; none on the simnet). After a build: `npm run check:mainnet` (builds the page with the mainnet wasm package and scans every shipped file, worker glue and `.wasm` included) and `npm run check:csp` (the built page under `vercel.json`'s headers in Chromium via `vite preview`: the CSP on the page and the worker, eval refused in both, the wasm glue running, framing refused; F6 part B: the figure under its own CSP in How it works' sandboxed frame, its tour running, an inline script refused, another origin unable to frame it; ports 4173 and 4174).
- **Deploy** (F6 part C, `docs/launch/site-deploy.md`): configuration in `web/.env.production` (template `.env.production.example`); `npm run csp:write` writes the CSP connect-src (the indexer origin, the resolver's four domains or `VITE_NODE_URL`'s origin; `scripts/csp.mjs`) into `vercel.json`; `npm run check:deploy` checks the artifact itself (the configuration, dist built with it, connect-src, check-bundle, W4 on the served `.wasm` in Node with a dev-package control; `-- --vercel` also `.vercel/output` against dist and its header rules). Vercel gets the site prebuilt (`vercel build` + `vercel deploy --prebuilt`); `vercel.json`'s install and build commands are `scripts/vercel-prebuilt.mjs`, which builds nothing and fails without a built dist. Never run Vercel commands without the owner.
- **Response headers** (spec 6.6): `vercel.json` is the one copy of the CSP and the other headers, in two rules that never overlap: the site (`/((?!figures/).*)`: `frame-ancestors 'none'`, `frame-src 'self'`) and the framed figures (`/figures/(.*)`: their inline script and style elements by hash, written by the figure build; style attributes inline; nothing else; `frame-ancestors 'self'`, X-Frame-Options SAMEORIGIN). Vercel serves them and `vite preview` applies the same per path (`vercelHeaders` in `vite.config.ts`). There is no CSP meta tag. The worker needs no `'unsafe-eval'`: the glue's `new Function` is js-sys's last-resort global lookup, never reached in a worker.

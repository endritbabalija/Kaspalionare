# M6 spec: K shards and limits

Status: draft for approval, 2026-10-13. Design references are to `docs/design.md` v0.4.1 with the M5 edits applied (DECISIONS 2026-10-13).

Interview answers:
- the ticket deposit becomes d = 0.13 KAS; P_MIN stays 0.05 KAS; claim fees under load are documented, not tuned;
- K, B_MAX and m_max stay 16, 4 and 50; M6 measures where each limit is hit, with the real scripts, and records that frontier;
- (after the spec review) K, R and m_max are recorded as **provisional**, pending the real-seed milestone that follows M6 and will change `draw()` and possibly `close()`; the spec names which M6 measurements depend on the drawer script size (A5a);
- the vault's share unit becomes SHARE_UNIT = 1 sompi, with a genesis floor V₀ ≥ 1 KAS;
- request griefing is mitigated with minimum request sizes of 10 KAS (MIN_DEPOSIT and a withdrawal minimum), plus the replace-by-fee argument, which is documented;
- the purchase conflict rate comes from a Rust model plus a new testnet-10 probe.

M6 builds:
- measurement tests for every transition at the final parameters and for the K, B_MAX and m_max frontier (`m6_measure`);
- a purchase-conflict model (`m6_conflict`) and a testnet-10 probe (`probe conflict-m6`);
- three constant changes in covenants (MIN_DEPOSIT in the vault, drawer and request), one new check in `vault.request_withdraw` (the withdrawal minimum), genesis changes (SHARE_UNIT, V₀ floor, d floor) and the fixture deposit d = 0.13 KAS;
- the cleanup of the dead M4 draw branch;
- the M6 section of `docs/costs.md` (size and mass per transition, minimums, frontier), and the final R, d, K, b_max and m_max in `docs/DECISIONS.md`.

No state layout changes. No transition changes how money moves.

## A4. Script changes

**`vault.sil`, `request_withdraw`, new check W4b** (after W4, before W5; tag `M6W4b_min`):

```
// ==== check W4b (M6, D86): w >= wmin or the whole position
{
    int q = (total_assets + VA) / W_MIN_VALUE;   // total_assets <= ASSETS_MAX (W1): sum <= 2^62
    int wmin = 1;
    if (q >= 1) {
        wmin = (total_shares + VS) / q;          // total_shares <= SHARES_MAX (W1): sum <= 2^62
    }
    require(w >= wmin || w == ps.shares); // mut:M6W4b_min
}
```

Value bound: if q ≥ 1, then q ≤ (A + 1) / W_V and wmin ≥ (S + VS) / q − 1 ≥ W_V (S + VS) / (A + 1) − 1. Multiplying by π = (A + 1) / (S + VS) gives w × π ≥ W_V − π. If q = 0, the vault's assets are below W_V − 1, so any w ≥ 1 is allowed. The bound uses the request-time price. The conversion price at the next draw may differ, which matters for griefing cost but not for safety.

**Constants:** `vault.sil` MIN_DEPOSIT → 10⁹, new W_MIN_VALUE = 10⁹ and VS = 1,000 (VA if not declared). `drawer.sil` MIN_DEPOSIT → 10⁹; comments updated (the C1 bound "2⁶² + 10⁸" becomes "2⁶² + 10⁹"). `request.sil` MIN_DEPOSIT → 10⁹. No other script changes.

## A6. Testnet-10 (`crates/tn10`, not part of `cargo test`; results in `docs/tn10-mass-check.md`)

- **New `probe conflict-m6`:** genesis (K = 16, scaled values as `draw-m3`), then n = 10 repetitions on fresh shards of:
  1. **Race.** Buys A and B are built on the same shard state and submitted back to back. Expected: B is rejected as a double spend.
  2. **Replace.** B is resubmitted through the replacement path at a higher feerate. Record whether it replaces A (D87 fact for covenant spends).
  3. **Chain.** Buy C is built on the unaccepted successor shard of the winning buy and submitted at once. Record acceptance or the error (research F3). Note: in the mempool the successor's creation DAA is UNACCEPTED_DAA_SCORE, pushed as −1, so shard check 6 (−1 < T) passes there. Consensus re-evaluates with the merging chain block's DAA score (DECISIONS O-S4-4 fact), so the late-buy bound still holds on chain.
  4. **Timing.** Record τ_chain (submit to accepted chained submission) and τ_merge (submit until the successor is chain-merged), as mean, median and max.
- **Re-runs at the final templates:** `buy-m1` at d = 0.13 (b = 1 with referral), `claim-m4` and `vault-m5`. The `vault-m5` re-run scales its deposit to ≥ MIN_DEPOSIT and its partial withdrawal to ≥ wmin, and keeps the δ − 1 negative case. All must be accepted, with masses equal to M6-a.

# M5 spec: house vault shares

Status: draft for approval (2026-10-12). Design references are to `docs/design.md` v0.4.1.

Interview answers:
- the aggregate conversion runs inside `draw()`, which creates one settlement record output when anything is pending;
- genesis gives the deployer a share position for V₀; prices use a virtual offset;
- shares are held in position UTXOs; a withdrawal proves ownership with an input from the owner's script, and may take part of a position;
- requests and positions carry the reserve R, refunded to the owner;
- the withdrawal cap counts the same draw's converted deposits;
- MIN_DEPOSIT = 1 KAS; a partial withdrawal payout below P_MIN accrues into the request;
- V_rec is the vault's total_assets after the conversions.

M5 builds:
- the vault's request entries `request_deposit()` and `request_withdraw()` and its new state fields;
- three new roles: the vault request (0x07), the settlement record (0x08) and the share position (0x0B, new);
- the conversion inside `draw()` (one new check block, one optional output, one new argument group);
- settlement of requests against their draw's record, and `refresh()` for the three new objects;
- genesis changes (deployer position, share count, template fields), the Rust reference, the builders and the tests.

## A1. Decisions (each becomes a DECISIONS row)

| # | Decision |
|---|---|
| D65 | **Conversion inside `draw()` (closes D40).** `draw()` converts the vault's pending totals in aggregate at its post-settlement price and creates **one settlement record** output, at a fixed index, iff pend_dep > 0 or pend_wsh > 0. Its input count does not change: no request is gathered. This matches design 5.5, which lists the record among `draw()`'s outputs; the milestone's "keeps `draw()`'s shape fixed" is read as "independent of the number of requests". The record's R is posted by the `draw()` caller and refunded to the recorded funder (the same funder_class/funder_key arguments as the pools) when the record is drained. |
| D66 | **Genesis shares and price defence (design 5.4 "dead shares or a virtual offset").** Genesis mints S₀ = floor(V₀ / SHARE_UNIT) shares, SHARE_UNIT = 1,000 sompi, into a **share position owned by the deployer** (a payout script of a D11 class). total_shares = S₀. Prices use a **virtual offset**: VS = 1,000 virtual shares and VA = 1 virtual sompi, so the price is (A + 1) / (S + VS). No division by zero is possible, whatever A and S are. The virtual shares' rounding share stays in the vault. Supersedes D50's total_shares = 0 at genesis. |
| D67 | **Share positions (new role 0x0B).** A position holds a share count and an owner (class + 33-byte key, D11). It is created by genesis, by a deposit settlement, or as the remainder of a partial withdrawal. **Withdrawal authorization:** `request_withdraw()` requires one input whose scriptPubKey equals the owner's script (`tx.inputs[i].scriptPubKey`, SilverScript `docs/TUTORIAL.md:1131`). That works for P2PK Schnorr, P2PK ECDSA and P2SH owners. A withdrawal may take part of a position: position' keeps the rest. Positions are not transferable and cannot be merged (out of scope). |
| D68 | **Values.** A request and a position each carry exactly R (the vault's reserve; the vault derives it as its value − total_assets − pend_dep), posted by the backer and returned to the owner at the final settlement. A withdrawal request also carries accrued prizes (D70). The record carries its remaining assets + R. |
| D69 | **Withdrawal cap (design 5.4, "withdrawals capped to keep L(r+1)").** The lock counts the same draw's converted deposits: converted withdrawals pay out at most V' + D_c − L', so the vault's total_assets after the conversions is ≥ L(r+1). The converted share count w_c is the largest w ≤ W whose payout fits; it is supplied as a witness and checked by "fits at w_c and fails at w_c + 1" (as D48). The rest, W − w_c, stays pending for the next draw. Each request's part of it is computed pro rata at settlement (D72). |
| D70 | **Minimums and modes.** A deposit request needs D ≥ MIN_DEPOSIT = 100,000,000 sompi (1 KAS). `draw()` converts the deposits only if the aggregate mint is ≥ ceil(D / MIN_DEPOSIT) and fits the share range. That guarantees every request at least one share (A6.4). Otherwise the record is in **refund mode**, and each deposit settlement repays its deposit. A zero-share mint is therefore impossible at both levels. A partly converted withdrawal pays its payout if it is ≥ P_MIN = 5,000,000 sompi (as D57); a smaller payout **accrues** into request' and is paid with that request's final settlement (as D56 ACCRUE). |
| D71 | **V_rec = total_assets after the conversions** (vault' total_assets), written into the round r+1 controller. J(r+1), G2 and L(r+1) are still fixed from V' before any conversion (design 5.4). |
| D72 | **Settlement by exact drain.** The record keeps remaining totals. Each settlement takes its pro-rata part of the *remaining* totals, rounded down, and subtracts it. The last settler of a side takes exactly what is left. So the parts sum exactly to the converted totals, nothing is left as dust, and settlement order cannot change the totals by more than one unit per settler. When both sides are drained, the record is consumed and its R is refunded to its funder. Formulas: A6. |
| D73 | **Wide arithmetic (R8).** a × b / c with operands up to 2⁶² cannot be formed in 64 bits, and the engine has no wide multiply (`OpMul` is checked 64-bit: rusty-kaspa v2.1.0 `crypto/txscript/src/opcodes/mod.rs:649-651`). Scripts use `mulfrac(a, r, c) = floor(a × r / c)` for 0 ≤ a ≤ 2⁶², 0 ≤ r < c ≤ 2⁶², computed by 63 unrolled double-and-add steps. Every intermediate stays below 2⁶³, and the result is ≤ a. The Rust mirror uses u128. |
| D74 | **Route of trust (R5, no hash cycle).** The **vault state** gains record_tpl, request_tpl and position_tpl, instance constants set at genesis and copied unchanged. The drawer reads record_tpl and request_tpl from the vault state it already authenticates, so the drawer state layout does not change. The position has VAULT_TPL as a constructor constant. The request has RECORD_TPL and POSITION_TPL as constructor constants. The record has none; its state carries request_tpl, written by `draw()`. Order: controller ← drawer ← {marker, vault, pool, record}; vault ← position; {record, position} ← request; pool ← ticket ← shard; controller ← params. |
| D75 | **Shape policy (as D60).** Covenant inputs come first, then 1..F_MAX funding inputs with the zero ID. Covenant outputs come first, all authorized by input 0. Plain outputs sit at fixed indices, and at most one change output comes last. Every plain output has the zero ID. The caller pays the fee from funding. |
| D76 | **`refresh()` on position, request and record** (D59 code, D_IDLE = 864,000). Positions can stay idle for years; the record is shared by all of a draw's backers. The vault gets no refresh: every `draw()` re-spends it. |
| D77 | **Anyone may settle** a request, as anyone may claim (D56): a settlement pays or mints only to the request's owner. Only the owner can *create* a withdrawal request (D67). Deposit requests are created by whoever pays D, naming any owner. |
| D78 | **Re-checks with stop rules.** (a) The worst `draw()` (DP21 with conversion and the record) and the `draw()` storage supremum with one more R output: stop and ask if any mass exceeds 90 %. (b) The marker's script bytes change (its DRAWER_TPL constant changes with the drawer), so `close()` K = 16 is re-measured: stop and ask above 90 %. (c) If the drawer exceeds SilverScript's 244-item stack limit (DECISIONS fact S3-6), stop and ask; do not restructure `draw()` unasked. |
| D79 | **Test fixtures (as D63).** Main positives run real genesis → requests → buys → `close()` → `draw()` → settlements. Range and malformed-state attacks use vaults, records, requests and positions fabricated as UTXOs under the instance covenant ID. Lineage makes those states unreachable, so these tests exercise R8 only. |

## A2. Constants

- Roles: ROLE_VAULT 0x06, ROLE_REQUEST 0x07, ROLE_RECORD 0x08 (fixed by D1), **ROLE_POSITION 0x0B** (new).
- Request kinds: 0 deposit, 1 withdrawal.
- SHARE_UNIT 1,000 (genesis builder only); VS 1,000; VA 1.
- MIN_DEPOSIT 100,000,000; P_MIN 5,000,000; D_IDLE 864,000.
- SHARES_MAX = TOTAL_MAX − VS, the largest total_shares, so S + VS ≤ 2⁶².
- ASSETS_MAX = TOTAL_MAX − 1, the largest V', so V' + VA ≤ 2⁶². This cannot bind: consensus caps any value at MAX_SOMPI ≈ 2.9 × 10¹⁸ < 2⁶² (DECISIONS fact S4-3).
- As before: F_MAX 8, TOTAL_MAX 2⁶², RESERVE_MAX 10¹⁰, DAA_MAX 5 × 10¹¹, SCRIPT_MAX 10⁶.
- Constructor constants: VAULT_TPL (position); RECORD_TPL and POSITION_TPL (request); DRAWER_TPL (vault, unchanged).

## A3. State layouts (field order = byte order; int = 8-byte payload)

**A3.1 Vault (0x06), extended:** role, round, total_assets, total_shares, pend_dep, pend_wsh, liability, **record_tpl[32]**, **request_tpl[32]**, **position_tpl[32]**. Value: total_assets + pend_dep + R. round = the last drawn round, so requests target round + 1. Every reader's `VaultState` (drawer) gains the three fields.

**A3.2 Request (0x07):** role, round (the target draw), kind (byte: 0 deposit, 1 withdrawal), amount (deposit sompi or withdrawal shares), owner_class (byte), owner_key[33]. Value: R + accrued (accrued = 0 for deposits).

**A3.3 Settlement record (0x08):** role, round (the draw that created it), request_tpl[32], refund (byte 0/1), dep_rem, mint_rem, wsh_rem, burn_rem, out_rem, funder_class (byte), funder_key[33]. Value: out_rem + refund × dep_rem + R.

**A3.4 Share position (0x0B):** role, round (the round of the draw that minted it; 0 at genesis; informational, never checked against anything), shares, owner_class (byte), owner_key[33]. Value: R.

**Ranges (R8), checked by every reader:**
- vault: role 0x06; 0 ≤ round < TOTAL_MAX; 0 ≤ total_assets ≤ ASSETS_MAX; 0 ≤ total_shares ≤ SHARES_MAX; 0 ≤ pend_dep ≤ TOTAL_MAX − total_assets; 0 ≤ pend_wsh ≤ total_shares; 0 ≤ liability ≤ TOTAL_MAX; 0 ≤ R = value − total_assets − pend_dep ≤ RESERVE_MAX.
- request: role 0x07; 1 ≤ round < TOTAL_MAX; kind ≤ 1; deposit amount in [MIN_DEPOSIT, TOTAL_MAX]; withdrawal amount in [1, SHARES_MAX]; owner_class ≤ 2 with the D11 key padding; R ≤ value ≤ TOTAL_MAX.
- record: role 0x08; 1 ≤ round < TOTAL_MAX; refund ≤ 1; every _rem in [0, TOTAL_MAX]; mint_rem ≤ SHARES_MAX; burn_rem ≤ wsh_rem; refund = 1 ⇒ mint_rem = 0; funder_class ≤ 2.
- position: role 0x0B; 1 ≤ shares ≤ SHARES_MAX; owner_class ≤ 2 with the D11 padding.

**A4.1 `request_deposit(byte owner_class, byte[33] owner_key)`**

| | Index | Object |
|---|---|---|
| Input | 0 | vault (round r) |
| Input | 1..n | funding, 1 ≤ n ≤ F_MAX, zero ID |
| Output | 0 | vault' (value + D) |
| Output | 1 | request (deposit, value R) |
| Output | 2 | change (optional, zero ID) |

|---|---|---|---|

| Input | 1 | position | position |

4. 1 ≤ w ≤ ps.shares; w ≤ total_shares − pend_wsh.

There is no cancel entry: a request can only be settled (design 5.4, irrevocable).

## A5. Conversion in `draw()` (new drawer check block, after check 17)

Notation: V' = vP (check 14), S = vt.total_shares, D = vt.pend_dep, W = vt.pend_wsh, L' = lNext (check 17), N = S + VS, M = V' + VA. Ranges: V' ≤ ASSETS_MAX and S ≤ SHARES_MAX (check 5 extended), so N, M ≤ 2⁶²; W ≤ S.

New arguments: `int wc` (withdrawal witness), `byte[] record_prefix`, `byte[] record_suffix`. The record's funder is the existing funder_class/funder_key.

**C1 Deposits.** If D = 0: ok = false and mint = 0. Otherwise q = N / M and r = N % M.
- ok = (q = 0 ∨ D ≤ (SHARES_MAX − S) / q).
- If ok, mint = D × q + mulfrac(D, r, M), then ok = ok ∧ mint ≤ SHARES_MAX − S ∧ mint ≥ (D + MIN_DEPOSIT − 1) / MIN_DEPOSIT.
- Converted: D_c = ok ? D : 0; mint_c = ok ? mint : 0; refund = (D > 0 ∧ ¬ok).

**C2 Withdrawals.** out(w) = mulfrac(M, w, N) for 0 ≤ w ≤ W (w < N, so this is defined; out(w) ≤ M). slack = V' + D_c − L' (≥ 0, because L' ≤ floor(V' × cap / 10⁴) ≤ V'; the sum is guarded).
- 0 ≤ wc ≤ W;
- out(wc) ≤ slack;
- wc = W, or out(wc + 1) > slack.

out_c = out(wc). out is monotone in w, so wc is unique.

**C3 Results.**
- vault': total_assets = V' + D_c − out_c, total_shares = S + mint_c − wc, pend_dep = 0, pend_wsh = W − wc, liability = L', round = r; the template fields are unchanged.
- rec = (D > 0 ∨ W > 0).
- If rec, the record is {round r, request_tpl = vt.request_tpl, refund, dep_rem = D, mint_rem = mint_c, wsh_rem = W, burn_rem = wc, out_rem = out_c, funder}. Its value is out_c + (D − D_c) + R.
- controller' v_rec = vault' total_assets (D71). J', J_boost', G2' and L' are unchanged from check 17, which uses V'.

**Changes to existing drawer checks:**
- check 5: the extended `VaultState` and its A3.1 ranges;
- check 13: nCov = 3 + np + rec; the record, if present, sits at index 3 + np, after the pools;
- check 20: out1.value = total_assets' + R (pend_dep' = 0); the record value; the output count uses the new nCov;
- check 21: the zero-ID loop starts at the new nCov;
- check 23: vault' as C3;
- check 24: v_rec = total_assets';
- new check 26: if rec, validateOutputStateWithTemplate(3 + np, record, vt.record_tpl, record_prefix, record_suffix). If not rec, nothing is written; record_prefix and record_suffix are ignored.

**Conservation (5.5), vault side:** vault (V + D + R) → vault' (V' + D_c − out_c + R) + record (out_c + D − D_c + R_new). The house settlement V → V' is unchanged from M3. The record's R comes from the caller's funding and is refunded at drain.

## A6. Settlement (request leads)

**A6.1 `settle(int rec_pl, int rec_sl)`.** s = request.amount, rc = the record.

| | Index | Deposit (convert) | Deposit (refund) | Withdrawal FINAL | Withdrawal PAY | Withdrawal ACCRUE |
|---|---|---|---|---|---|---|
| Input | 0 | request | request | request | request | request |
| Input | 1 | record | record | record | record | record |
| Input | 2.. | funding | funding | funding | funding | funding |
| Output | 0 | record' (unless drained) | same | same | same | same |
| Output | next | position (sh, R) | — | — | request' | request' (+ pay) |
| Output | next (plain) | — | payout s + R | payout pay + value | payout pay | — |
| Output | next (plain) | refund R to funder (if drained) | same | same | same | same |
| Output | last | change (optional) | same | same | same | same |

Checks:
1. activeInputIndex = 0; cov; own A3.2 ranges; rec_pl, rec_sl ∈ [0, SCRIPT_MAX].
2. OpCovInputCount(cov) = 2; OpInputCovenantId(1) = cov; 3 ≤ tx.inputs.length ≤ 2 + F_MAX; inputs ≥ 2 have the zero ID.
3. rc = readInputStateWithTemplate(1, rec_pl, rec_sl, RECORD_TPL); A3.3 ranges; in1.value = rc.out_rem + rc.refund × rc.dep_rem + R_rc with 0 ≤ R_rc ≤ RESERVE_MAX; **rc.round = round** (the wrong draw's record is rejected).
4. **Amounts (D72):**
   - Deposit: s ≤ rc.dep_rem. If rc.refund = 1, sh = 0 and the payout is s. Otherwise sh = (s = rc.dep_rem) ? rc.mint_rem : mulfrac(rc.mint_rem, s, rc.dep_rem), and **sh ≥ 1**.
   - Withdrawal: s ≤ rc.wsh_rem. conv = (s = rc.wsh_rem) ? rc.burn_rem : mulfrac(rc.burn_rem, s, rc.wsh_rem). pay = 0 if rc.burn_rem = 0, rc.out_rem if conv = rc.burn_rem, else mulfrac(rc.out_rem, conv, rc.burn_rem). left = s − conv.
5. **Record':** dep' = dep_rem − s (deposit); mint' = mint_rem − sh; wsh' = wsh_rem − s (withdrawal); burn' = burn_rem − conv; out' = out_rem − pay. drained = (dep' = 0 ∧ wsh' = 0).
6. **Mode:** deposit-convert, deposit-refund, or withdrawal FINAL (left = 0), PAY (left > 0 ∧ pay ≥ P_MIN) or ACCRUE (left > 0 ∧ pay < P_MIN).
7. **Covenant outputs (R2):** nCov = [¬drained] + [deposit-convert ∨ PAY ∨ ACCRUE]; OpAuthOutputCount(0) = nCov; OpAuthOutputIdx(0, j) = j; OpCovOutputCount(cov) = nCov.
8. **Output count (R7):** nOut = nCov + [payout] + [drained] + ch, ch ∈ {0, 1}; every output ≥ nCov has the zero ID.
9. **Values:**
   - record' = out' + refund × dep' + R_rc;
   - position = in0.value (= R);
   - request' = in0.value (PAY) or in0.value + pay (ACCRUE, guarded);
   - payout = s + in0.value (refund), pay + in0.value (FINAL, guarded) or pay (PAY);
   - refund output = R_rc.
10. **Scripts (D11):** payout to payoutSpk(owner); the refund output to payoutSpk(rc.funder).
11. If ¬drained: validateOutputStateWithInputTemplate(0, record' with the new remainders, every other field unchanged, from input 1).
12. Deposit-convert: validateOutputStateWithTemplate(position index, position {rc.round, sh, owner}, POSITION_TPL).
13. PAY or ACCRUE: validateOutputState(request' index, {round + 1, kind 1, left, owner}).

**Record `request_leg(int req_pl, int req_sl)` (delegate):** RL1 activeInputIndex = 1; RL2 OpInputCovenantId(0) = own ID; RL3 OpAuthOutputCount(1) = 0; RL4 readInputStateWithTemplate(0, …, request_tpl from own state) has role 0x07 and round = own round.

**A6.2 Drain invariants (proved in the spec review and tested in VP12):**
- the remaining ratio mint_rem / dep_rem never decreases, because each settler takes the floor;
- with mint ≥ ceil(D / MIN_DEPOSIT) and every s ≥ MIN_DEPOSIT, every sh ≥ 1;
- burn_rem ≤ wsh_rem holds after every step;
- the last settler of a side receives the side's exact remainder;
- Σ sh = mint_c, Σ conv = wc and Σ pay = out_c;
- Σ left over all of a record's withdrawal requests = W − wc = the vault's carried pend_wsh, so each request' (round + 1) is covered by the next draw's pending total.

## A7. `refresh()` on position, request and record

The same code as M4 A6 (D59): self-authorized byte-identical successor with the same value; creation = OpTxInputDaaScore(0) with 0 ≤ creation < DAA_MAX; tx.daa ≥ creation + D_IDLE; exact shape.

## A8. Arithmetic (R8)

- `mulfrac(a, r, c)`: requires 0 ≤ a ≤ 2⁶², 0 ≤ r < c ≤ 2⁶². It keeps (Q, X) with prefix × r = Q × c + X, 0 ≤ X < c, over the bits of a from bit 62 down. Each step doubles X (< 2⁶³), subtracts c once if needed, adds r (X + r < 2c ≤ 2⁶³) and subtracts c once if needed. Q ≤ the final result ≤ a.
- Every subtraction is formed only after the matching comparison. Every sum is guarded as `x ≤ LIMIT − y`.
- A violated range in `draw()` rejects only states that lineage cannot produce (D79). No input that lineage *can* produce makes C1–C3 reject: deposits that cannot convert take the refund branch instead.

## A11. Out of scope

- Share transfer, merging positions, KCC20 share tokens (research L4).

## A12. Done criteria (from `docs/milestones.md`, made concrete)

1. Requests convert at the share price set by their target draw after settlement, so a new backer cannot capture returns from earlier rounds (VP4, VP8, VP14).
2. Tests reject:
   - a zero-share deposit (VA1);
   - cancelling a request (VA2);
   - settling against the wrong draw's record (VA3);
   - a second settlement (VA4);
   - a withdrawal that takes the vault below L(r+1) (VA5);
   - share × price overflow boundaries (VA6, VP12).
3. J(r+1) is fixed before that draw's conversions (VP4, VA14).
4. Withdrawing below the liability L = J_house + G2 × (m − 1) of the round whose jackpot is fixed is rejected before that round is drawn (VA5; VP6, VP14 invariant). So are a conversion at a stale or future price (VA7) and a double conversion (VA8).
5. Value is conserved in every request, conversion and settlement (VP13).
6. The marker's bytes change, so `close()` K = 16 is re-measured (M5-d). `draw()` is re-measured too (M5-b, M5-c). Stop and ask above 90 %.
7. The full `cargo test` passes, M0–M4 included. The covenant-reviewer has run. Rows D65–D79 are in DECISIONS, and M5-f is in `docs/tn10-mass-check.md`.

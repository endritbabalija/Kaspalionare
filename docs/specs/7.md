## A0. First task: can the harness engine exercise `OpChainblockSeqCommit` locally?

**Yes.** Evidence:

1. The opcode (`crypto/txscript/src/opcodes/mod.rs:1389-1404`) pops a 32-byte block hash and consults `vm.ctx.seq_commit_accessor`. With no accessor it fails with `InvalidOpcode` (`:1390-1393`), which is what `harness::execute` does today (`crates/harness/src/lib.rs:107` builds `EngineCtx` without one). With an accessor it calls `is_chain_ancestor_from_pov(hash)` (`None` → `BlockAlreadyPruned`, `Some(false)` → `BlockNotSelected`) and `seq_commitment_within_depth(hash)` (`None` → `BlockIsTooDeep`), then pushes the 32-byte commitment. The trait is `kaspa_txscript::SeqCommitAccessor` (`crypto/txscript/src/seq_commit_accessor.rs:3-6`), injected by `EngineCtx::with_seq_commit_accessor_opt` (`engine_context.rs:32-35`). rusty-kaspa's own script tests inject a mock (`crypto/txscript/src/lib.rs:2483-2520`).
2. Consensus builds the accessor as `SeqCommitAccessor::new(selected_parent, reachability, headers, finality_depth)` for block validation and for **mempool** validation (`consensus/src/pipeline/virtual_processor/utxo_validation.rs:372-373, 445`), so a transaction using the opcode is relayed. The real accessor (`consensus/src/model/services/seq_commit_accessor.rs:31-45`) answers `is_chain_ancestor_from_pov` with `try_is_chain_ancestor_of(block, selected_parent)` and admits a block iff `block.blue_score + F > selected_parent.blue_score` (`:8-10, 36-44`). F = `finality_depth` = BPS × FINALITY_DURATION = 10 × 43,200 = **432,000** for mainnet and testnet-10 (`consensus/core/src/config/bps.rs:92-93`, `constants.rs:70`; both `BlockrateParams::new::<10>()`, `params.rs:643, 699`).
3. `harness::ChainSim` (A7) implements the trait over a fabricated chain: a map hash → (blue score, DAA score, selected parent, SeqCommit, on-chain flag), a POV blue score and F. It reproduces every failure mode (unknown or pruned, not on the chain, too deep) and reorgs (replace the chain set and POV, re-execute). The commitments are computed with the KIP-21 hashers of `kaspa_hashes` (`crypto/hashes/src/hashers.rs:39-49`: `SeqCommitMerkleBranch` = "SeqCommitmentMerkleBranchHash", `SeqCommitMergesetContext`, `SeqCommitActivityRoot`, …, all keyed BLAKE3 with the tag zero-padded to 32 bytes, `:120-138`), so the script's preimage recomputation is tested against the consensus hashers.
4. What the local engine cannot show: the real accessor's point of view, the activation state of KIP-21 semantics on testnet-10 (accessor condition 4, `kip-0021/seqcommit-accessor.md` "Opcode Mechanics"), the RPC reconstruction of a real block's preimage, relay through the public mempool, and that lock_time and the window interact as the drift argument (A5) claims. These run on testnet-10 (A9, probes `draw-m7` and `void-m7`). Every attack test runs locally.

## A5. Why void and draw cannot both be valid (the drift argument)

Let C be the chain block validating a transaction and P_pov its selected parent (the opcode's point of view, `seqcommit-accessor.md` "Opcode Mechanics"; `utxo_validation.rs:373`). Void requires lock_time ≥ D + 2F, and consensus accepts a DAA lock only if lock_time < daa(C) (`transaction_validator/tx_validation_in_header_context.rs:61-70`), so daa(C) > D + 2F. The anchor has daa(X) ≤ daa(P) + MERGESET_MAX ≤ D − 1 + M (M = 248). Along the chain from X to C, DAA grows by |mergeset \ non_daa| per chain block and blue score by |mergeset blues|, so bs(C) − bs(X) ≥ (daa(C) − daa(X)) − reds, where reds counts the red blocks merged by chain blocks in that span, and bs(P_pov) ≥ bs(C) − M. Hence bs(P_pov) − bs(X) > 2F − 2M − reds ≥ F whenever reds ≤ F − 2M = 431,504, and then `X.blue_score + F ≤ P_pov.blue_score`: the accessor refuses X (`seq_commit_accessor.rs:8-10, 36-44`) and `draw()` is impossible from that point of view. Conversely, while `draw()` is possible the void lock cannot hold. The assumption (fewer than about 431,000 red blocks merged in 24 h, i.e. not a sustained majority attack) is recorded with the decision. A unit test checks the inequality over the parameter grid (SP9). [Am-4: the bound holds up to reds = F − 2M + 2; lock_time is checked against the merged block B that contains the transaction and the point of view is the selected parent of the chain block that merges B, not daa(C); the conclusion holds.]

## A6. Manipulation-cost argument (milestone criterion 2)

Parties and levers, with X = the first chain block with DAA ≥ D:

1. **The closer.** D is the DAA score of the chain block that accepts `close()` plus SEED_OFFSET. The closer picks neither (it can only choose when to submit), every candidate anchor is strictly after that chain block, and no block's hash is known before it is found. R1 is closed: funding inputs of any age give the same D (SP5).
2. **The miner of the anchor block (withholding).** It knows X.hash and the outcome before publishing. If it withholds X, the next block found at that DAA transition (by anyone, with probability 1 − α by others) becomes the anchor. Cost: if the withheld block is published shortly after it is normally still blue and rewarded, so the cost is between 0 and one block subsidy (`coinbase.rs:222`, `calc_block_subsidy`) plus its fees; it is not the cost of a competing chain. Gain: a fresh sample worth E[payout] = c·EV_t for c held combinations. Expected extra samples ≈ α/(1 − α) (the miner re-samples while it keeps finding the replacement). Per round: profit = c·p·[α/(1−α)·(1−ε) − ε] − (α/(1−α))·cost, where ε = 1 − EV_t/p is the player's expected loss fraction, which the game-size rule (design 4.6) keeps positive. **Profitable iff α > ε** (cost ≈ 0). At the starting values ε is about 0.27 for an ordinary player (s_F + s_C + s_D + the unreturned part of s_t, plus the backers' edge e on the house share) and about 0.17 for a self-referring one; the implementation session records the exact figure from `game::round_amounts`. A J bound does not help: the gain is c·EV_t, bounded by the game-size rule per ticket and unbounded in c. **Not enforced in M7**; OPEN release-gate row (D100). [Am-5: 0.27 / 0.17 hold only where the edge rule binds; where the whale check binds ε is lower (computed in DECISIONS, "D100 amended"), down to about 0 at margin = 1.0 for a player who also takes the referral and both caller rewards; α is rentable burst hashrate, because the anchor time is predictable to within seconds.]
3. **The miner of the anchor block (grinding before PoW).** X.hash changes only with a new PoW solution (the header, including parents, timestamp and nonce, is what is hashed, and the PoW covers the same fields), so there is no free menu. Several own blocks found inside the propagation window give several samples; they are counted in α/(1−α).
4. **Any miner (chain selection).** Which of several parallel candidates at the DAA transition becomes the chain block is decided by blue work (and a hash tie-break); omitting a heavier tip from one's parents makes one's own block lighter and it loses the chain position unless the attacker sustains the race. Cost: a race against the rest of the network, not a block. [Am-5: a miner of the next level can leave a visible honest candidate out of its parents and make up the weight with its own extra blocks, which stay blue and rewarded; this rejects honest candidates as well as its own and is cheaper than withholding.]
5. **The caller of `draw()`.** It can only present the unique X (SA1–SA4); delaying gains nothing (the outcome is fixed once X exists) and risks the window; a void has no winners, so letting the window pass never pays. Forcing a void against a known jackpot hit requires censoring `draw()` for 12 h: design §10 "persistent censorship", fundamental.
6. **Reorg.** A `draw()` whose X leaves the selected chain is re-evaluated and fails (`seqcommit-accessor.md` "Reorg Behavior"); a new anchor then exists on the new chain. Rewriting the chain below X after a draw is the usual finality assumption (F = 12 h).
7. **Nobody re-rolls after a missed window.** Void has no winners; a draw after a void is impossible (drawn = 1); a draw outside the window is impossible (opcode); the marker cannot be re-created with a later creation DAA (no refresh, D99; `close()` consumes the shards once).

Conclusion recorded in the spec and DECISIONS: the covenant removes every selection surface except the anchor miner's withholding, whose value is one extra sample per block found at the anchor; that bias is bounded by α against ε, not by J, and is accepted for M7 with the VDF+ZK layer as the release-gate fix (D100).

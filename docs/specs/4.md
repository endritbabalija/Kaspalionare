# M4 spec: `claim()`, `return_deposit()` and `refresh()`

Status: draft for approval, 2026-10-10. Design references are to `docs/design.md` v0.4.1.

Interview answers:
- the ticket leads `claim()` (deviation from R6);
- a prize below P_MIN accrues into the ticket;
- `return_deposit()` uses both design 7.5 paths, with D_RET = 14 days;
- `refresh()` covers the marker, pools and tickets, with D_IDLE = 24 h.

M4 builds:
- the ticket's real code: `claim()`, `return_deposit_after()`, `return_deposit_with_pool()` and `refresh()`. It replaces the D13 placeholder.
- the pool's `ticket_leg()` (replacing the M3 placeholder `claim()`) and `refresh()`;
- the marker's `refresh()`;
- the drawer and pool layout additions the ticket route needs;
- the Rust reference, the builders and the tests.

## A1. Decisions (each becomes a DECISIONS row)

| # | Decision |
|---|---|
| D53 | **The ticket leads `claim()` (deviation from R6: "in `claim()` the pool validates the shape").** The ticket holds the claim code: K proofs, the tier match, the prize, every output. It authorizes pool' and ticket' (input 0). The pool is a delegate whose `ticket_leg` checks that input 0 is a genuine ticket of its round. **Why:** the K-proof code is about 16 × 1.24 kB (as drawer check 9, costs M3-c). In the pool, every absorbed pool and the pool template in `draw()`'s sigscript would each add about 25 kB. That would push DP21 from 36.9 % to about 97 % transient and force A_MAX below the up to 7 pools each `draw()` creates. In the ticket, the cost lands on `buy()`, whose ticket prefix/suffix argument grows (transient about +100k), while storage remains `buy()`'s binding mass (M4-d). |
| D54 | **Route of trust (R5, no hash cycle).** The ticket has POOL_TPL as a *constructor constant*. The pool cannot hold the ticket hash as a constant (cycle), so **drawer state** gains `ticket_tpl` (an instance constant set at genesis and copied unchanged, as D49). `draw()` writes it into every new **pool state** (check 25). Order: controller ← drawer ← {marker, vault, pool} ← ticket ← shard; controller ← params. The shard keeps TICKET_TEMPLATE_HASH as a constructor constant (M1); its value changes, its size does not. |
| D55 | **The pool state gains `reserve`** (= ctrl.reserve, written by `draw()` check 25). The ticket can then require prize ≤ remaining = value − reserve, so a claim can never take a pool into its reserve. R is an immutable instance value, and the round result already carries it (R4, A9). |
| D56 | **Claim modes, decided by rule (closes the 2026-10-10 open row on the minimum non-final prize).** A claim spends one ticket and one pool and claims one bundle index i, with bit = 2^i. "Final" means every other index of the ticket is already claimed: (claimed \| bit) = 2^b − 1. The prize is prize = floor(slice / h). The modes are:<br>- **FINAL:** the ticket is consumed and the payout is prize + ticket value.<br>- **PAY** (not final, prize ≥ P_MIN): payout = prize, and ticket' keeps its value.<br>- **ACCRUE** (not final, prize < P_MIN, including 0): there is no payout output, and ticket' value = ticket value + prize.<br>A third party may submit any claim, because no mode moves money away from the ticket's payout script. A ticket's value is therefore d × b plus accrued prizes, and FINAL and `return_deposit()` pay the whole value. |
| D57 | **P_MIN = 0.05 KAS (5,000,000 sompi), a ticket template constant,** to be confirmed by M4-c. P_MIN is the smallest value, rounded up to 0.01 KAS, for which the worst PAY-mode claim is within 90 % of storage mass. The worst case is b = 2 and d = 0.11 KAS, so ticket' is 0.22 KAS, with pool' at R. Estimate: 450,000 − 4C/0.22 KAS − 4C/R − C/1 KAS = 234,500, so P ≥ 0.0426 KAS (matches the 2026-10-10 M0 row). If M4-c gives a different value, the constant changes and a DECISIONS row records it. The bound depends on d, so the **genesis builder requires d ≥ D_CLAIM_FLOOR = 0.11 KAS**. M6 revisits both. |
| D58 | **`return_deposit()` confirmed (design 7.5 proposal), two entries.** **(a) `return_deposit_with_pool`:** co-spends a pool of the ticket's round with tx.daa ≥ pool.deadline; the pool is recreated byte-identical with the same value. **(b) `return_deposit_after`:** the ticket alone, with tx.daa ≥ T + D_RET. **D_RET = 12,096,000 DAA (14 days at 10 BPS, D23 source).** Both entries consume the ticket, pay its whole value to its payout script and forfeit unclaimed indices. Path (b) shortens the 7-day window only if `close()` + `draw()` run more than about 6.5 days after T (the parked missed-draw item). |
| D59 | **`refresh()` on marker, pool and ticket.** The object is spent into a byte-identical successor with the same value, the same template and the same covenant ID, authorized by itself. **D_IDLE = 864,000 DAA (24 h, below the ~30 h pruning horizon).** It requires creation ≥ 0 and tx.daa ≥ creation + D_IDLE, where creation = OpTxInputDaaScore(own input). **R3 note:** this is a rate limit on griefing, measured from the last spend, and not a lottery deadline. It moves no deadline, T or seed_ref, because those stay in state. The check creation ≥ 0 rejects an input whose parent is unaccepted (the score is −1, DECISIONS fact row O-S4-4). The controller, shards, params and vault get no refresh, because they are re-spent every round (R4) and shard bytes cost transient × K at `close()`. |
| D60 | **Shape policy for M4 transitions (as D2/D29).** Covenant inputs come first and then 1..F_MAX funding inputs with the zero ID. Covenant outputs come first, all authorized by input 0. Plain outputs sit at fixed indices, and at most one change output comes last. Every plain output has the zero ID. The caller pays the fee from funding, so no covenant value pays fees. |
| D61 | **Same covenant ID (closes the M1 review row on look-alike tickets).** Every ticket entry that co-spends a pool requires OpInputCovenantId(1) = own ID, and the pool's `ticket_leg` requires OpInputCovenantId(0) = own ID. A ticket minted by a look-alike shard under a fresh ID can therefore never touch a genuine pool. |
| D62 | **Proof format as `draw()`:** leaves are 2m·k bytes (each shard's counts at the combination's rank) and siblings are 576·k bytes. The leaf is Z_0 when all counts are zero, else H(0x00 ‖ rank (3 B) ‖ counts). **M_CLAIM = 50 = M_DRAW** is a ticket template constant (128-byte zero buffer, as drawer check 9). h is the exact sum of the K counts at the combination's bonus. |
| D63 | **Test fixtures:** main positives run real genesis → buys → `close()` → `draw()` → claims. Range and malformed-state attacks use tickets and pools fabricated directly as UTXOs under the instance covenant ID (as D14 and D33). Lineage makes such states unreachable on chain, so these tests exercise R8 only. |
| D64 | **Re-checks with stop rules:**<br>- A_MAX: if DP21 with the new pool code exceeds 90 % of any mass, stop and ask (D44);<br>- `close()` K = 16 (the marker changed): stop and ask if any mass exceeds 90 %;<br>- `buy()` (the ticket template grew): stop and ask if any mass exceeds 90 %. |

## A2. Constants

**Ticket template constants:**
- ROLE_TICKET 0x05 and ROLE_POOL 0x04;
- K_MAX 16, M_CLAIM 50, B_MAX 4, F_MAX 8, DEPTH 18, PATH 576 and COUNT_MAX 32,767;
- P_MIN 5,000,000, D_RET 12,096,000 and D_IDLE 864,000;
- DAA_MAX 5·10¹¹, TOTAL_MAX 2⁶², RESERVE_MAX 10¹⁰ and SCRIPT_MAX 10⁶;
- POOL_TPL (constructor constant).

**Pool and marker:** D_IDLE, F_MAX, plus their existing constants.

**Genesis builder:** D_CLAIM_FLOOR = 11,000,000 sompi.

Tier codes are as M3 A2: 0 jackpot, 1 second prize, 2..6 = (4+b, 4, 3+b, 3, 2+b).

## A3. State layouts (field order = byte order; int = 8-byte payload)

**A3.1 Ticket (0x05): layout unchanged** (M1 4.2): role, round, deadline (T), b, bundle byte[24], claimed byte[1], payout_class, payout_key byte[33]. Value: d × b + accrued. Bit i of claimed[0] (least significant first) marks index i.

**A3.2 Drawer (0x0A):** role, round, pool_tpl[32], vault_tpl[32], **ticket_tpl[32]** (new), f_min, claim_window, draw_window. Every reader's `DrawerState` struct (marker, vault and pool legs) gains the field.

**A3.3 Pool (0x04):** role, round, tier, slice, win[6], m, k, roots[512], deadline, **ticket_tpl[32]** (new), **reserve** (new), funder_class, funder_key[33]. Value: remaining + reserve.

**A3.4 Marker:** layout unchanged; the `refresh()` entry is added.

**Ranges (R8), checked by the ticket when it reads its own state and the pool:**
- ticket: role = 0x05; 1 ≤ round < TOTAL_MAX; 0 ≤ deadline < DAA_MAX; 1 ≤ b ≤ B_MAX; payout_class ≤ 2; 0 ≤ input value ≤ TOTAL_MAX;
- pool: role = 0x04; tier ≤ 6; 0 ≤ slice ≤ TOTAL_MAX; 2 ≤ m ≤ M_CLAIM; 1 ≤ k ≤ K_MAX; 0 ≤ deadline < DAA_MAX; 0 ≤ reserve ≤ RESERVE_MAX; reserve ≤ input value ≤ TOTAL_MAX.

## A4. `claim()` (ticket entry; leader)

**Shape:**

| | Index | FINAL | PAY | ACCRUE |
|---|---|---|---|---|
| Input | 0 | ticket | ticket | ticket |
| Input | 1 | pool | pool | pool |
| Input | 2..1+n | funding, 1 ≤ n ≤ F_MAX, zero ID | same | same |
| Output | 0 | pool' | pool' | pool' |
| Output | 1 | payout (prize + ticket value) | ticket' | ticket' (+ prize) |
| Output | 2 | change (optional) | payout (prize) | change (optional) |
| Output | 3 | — | change (optional) | — |

nCov = 1 (FINAL) or 2. Output count = nCov + [PAY] + ch, with ch ∈ {0, 1}.

**Arguments:** `claim(int idx, byte[] leaves, byte[] siblings, int pool_pl, int pool_sl)`.

**Checks, in order (test IDs cite these numbers):**
1. activeInputIndex = 0; cov = OpInputCovenantId(0); own state and input 0 value in the A3 ranges; pool_pl, pool_sl ∈ [0, SCRIPT_MAX]; 0 ≤ idx < b.
2. **Inputs (R2):** OpCovInputCount(cov) = 2; OpInputCovenantId(1) = cov (D61); 3 ≤ tx.inputs.length ≤ 2 + F_MAX; every input ≥ 2 has the zero ID.
3. **Pool:** pl = readInputStateWithTemplate(1, pool_pl, pool_sl, POOL_TPL); the A3 pool ranges; pl.round = round.
4. **Index:** bit = 2^idx (table 1, 2, 4, 8); c = unsigned(claimed[0]); (c / bit) % 2 = 0.
5. **Combination:** comb = bundle[6·idx .. 6·idx + 6]. n1..n5 and bonus are read unsigned. 1 ≤ n1 < … < n5 ≤ 30 and 1 ≤ bonus ≤ pl.m. These are re-checked, although `buy()` checked them, because the slices below depend on them. rank = colex rank (M1 3.1).
6. **Tier:** w1..w5 and wb come from pl.win; matched = Σ_{i,j} [n_i = w_j]; bm = [bonus = wb]. tier = 0 if (5, bm), 1 if (5, ¬bm), 2 if (4, bm), 3 if (4, ¬bm), 4 if (3, bm), 5 if (3, ¬bm), 6 if (2, bm); any other case rejects. Require tier = pl.tier.
7. **Proofs (D62):** leaves.length = 2·pl.m·pl.k and siblings.length = PATH·pl.k. For each i < pl.k:
   - counts_i = leaves[2m·i .. 2m(i + 1)];
   - leaf_i = Z_0 if counts_i is all zero, else H(0x00 ‖ rank ‖ counts_i);
   - walking leaf_i up 18 levels with siblings[PATH·i ..] reaches pl.roots[32i .. 32i + 32];
   - c_i = unsigned counts_i[2(bonus − 1) .. 2·bonus] ≤ COUNT_MAX, and h += c_i.
8. **Prize:** h ≥ 1; prize = pl.slice / h; remaining = in1.value − pl.reserve; prize ≤ remaining.
9. **Mode (D56):** final = ((c \| bit) = 2^b − 1), computed as c + bit = 2^b − 1, since bit is unset by check 4. pay = ¬final ∧ prize ≥ P_MIN. nCov = final ? 1 : 2.
10. **Covenant outputs (R2):** OpAuthOutputCount(0) = nCov; OpAuthOutputIdx(0, j) = j for j < nCov; OpCovOutputCount(cov) = nCov.
11. **Output count and plain outputs (R7):** nOut = nCov + [pay] + ch with ch ∈ {0, 1}; every output ≥ nCov has the zero ID.
12. **Values (R7):**
    - out0 = in1.value − prize;
    - FINAL: prize ≤ TOTAL_MAX − in0.value, and out1 = in0.value + prize;
    - PAY: out1 = in0.value and out2 = prize;
    - ACCRUE: prize ≤ TOTAL_MAX − in0.value, and out1 = in0.value + prize.
13. **Payout script (D11):** the payout output (out1 for FINAL, out2 for PAY) has scriptPubKey = payoutSpk(payout_class, payout_key).
14. **pool':** validateOutputStateWithInputTemplate(0, pool state unchanged, from input 1).
15. **ticket'** (not FINAL): validateOutputState(1, ticket with claimed = c + bit, every other field unchanged).

**Pool `ticket_leg(int ticket_pl, int ticket_sl)` (delegate):**
- PT1: activeInputIndex = 1;
- PT2: OpInputCovenantId(0) = own ID (D61);
- PT3: OpAuthOutputCount(1) = 0;
- PT4: ticket_pl and ticket_sl ∈ [0, SCRIPT_MAX]; readInputStateWithTemplate(0, …, ticket_tpl from own state) has role 0x05 and round = own round.

It serves `claim()` and `return_deposit_with_pool()`. These are the only ticket entries that allow a second covenant input, and both validate pool'.

**Conservation (5.5):** pool (Q) + ticket (d·b + acc) = pool' (Q − prize) + one of:
- FINAL: payout (prize + d·b + acc);
- PAY: ticket' (d·b + acc) + payout (prize);
- ACCRUE: ticket' (d·b + acc + prize).

Funding = change + fee. Reserves do not move.

## A5. `return_deposit()` (ticket entries; leader)

**`return_deposit_after()`** (path b; no arguments, as the M1 `locked()` entry):

1. activeInputIndex = 0; own ranges.
2. OpCovInputCount(cov) = 1; 2 ≤ tx.inputs.length ≤ 1 + F_MAX; every input ≥ 1 has the zero ID.
3. tx.daa ≥ deadline + D_RET (deadline < DAA_MAX, so the sum < 2⁶³).
4. OpAuthOutputCount(0) = 0; OpCovOutputCount(cov) = 0.
5. tx.outputs.length ∈ {1, 2}; every output has the zero ID.
6. out0.value = in0.value, and out0.scriptPubKey = payoutSpk(payout_class, payout_key).

**`return_deposit_with_pool(int pool_pl, int pool_sl)`** (path a):

1. As above, plus the template-length ranges.
2. OpCovInputCount(cov) = 2; OpInputCovenantId(1) = cov; 3 ≤ tx.inputs.length ≤ 2 + F_MAX; inputs ≥ 2 have the zero ID.
3. pl = readInputStateWithTemplate(1, …, POOL_TPL): role 0x04 and pl.round = round, plus the A3 pool ranges.
4. tx.daa ≥ pl.deadline.
5. OpAuthOutputCount(0) = 1; OpAuthOutputIdx(0, 0) = 0; OpCovOutputCount(cov) = 1.
6. tx.outputs.length ∈ {2, 3}; every output ≥ 1 has the zero ID.
7. out0.value = in1.value; validateOutputStateWithInputTemplate(0, pool state unchanged, from input 1).
8. out1.value = in0.value, and out1.scriptPubKey = payoutSpk(payout_class, payout_key).

## A6. `refresh()` (marker, pool and ticket; same code in each)

`refresh()` takes no arguments.

1. activeInputIndex = 0; cov = OpInputCovenantId(0).
2. OpCovInputCount(cov) = 1; 2 ≤ tx.inputs.length ≤ 1 + F_MAX; inputs ≥ 1 have the zero ID.
3. **Idle (D59):** creation = OpTxInputDaaScore(0); 0 ≤ creation < DAA_MAX; tx.daa ≥ creation + D_IDLE.
4. OpAuthOutputCount(0) = 1; OpAuthOutputIdx(0, 0) = 0; OpCovOutputCount(cov) = 1.
5. tx.outputs.length ∈ {1, 2}; output 1, if present, has the zero ID.
6. out0.value = in0.value.
7. validateOutputState(0, every field unchanged). This builds the successor from the same template and the same state, so it is byte-identical.

The ticket's own-state ranges are not needed for refresh: nothing is computed from them. The marker's refresh leaves seed_ref and the funder unchanged, so a refreshed marker is still drawn by the drawer (it has the same template, read through ctrl.marker_tpl).

## A7. Changes to existing scripts

- **drawer.sil:**
  - check 1 adds no range for ticket_tpl;
  - check 22 copies ticket_tpl;
  - check 25 writes ticket_tpl: ticket_tpl and reserve: ctrl.reserve into every new pool;
  - check 18 reads the new `PoolState`.
  Nothing else changes.
- **pool.sil:** the new layout. `claim()` is replaced by `ticket_leg`, and `refresh()` is added; `absorb_leg` is unchanged apart from the struct.
- **marker.sil, vault.sil:** the `DrawerState` struct gains ticket_tpl. The marker adds `refresh()`.
- **ticket.sil:** the real code (A4–A6) with the constructor constant POOL_TPL.
- **shard.sil:** unchanged source; its TICKET_TEMPLATE_HASH value changes.
- **controller.sil, params.sil:** unchanged.
- **genesis:**
  - the drawer state gains ticket_tpl = the compiled ticket hash, checked in `validate()`;
  - d ≥ D_CLAIM_FLOOR (D57);
  - the `Templates` compile order follows D54.

## A8. Off-chain code (Rust, `crates/lottery`)

- `state`: TicketState decode/encode (exists from M1); PoolState and DrawerState with the new fields.
- `game`: `tier_of(comb, win)`, `claim_amount(slice, h)` and `claim_mode(claimed, b, idx, prize)`. Each mirrors the script step for step.
- `claim` (new module): `ClaimCase` (all three modes), `ReturnCase` (paths a and b) and `RefreshCase` (marker, pool, ticket) build full transactions: compute budgets via `ComputeBudget::checked_covering_script_units`, signed funding, and lock_time and sequence per the check 7 fact row. `ClaimExpected` is the reference for every output.
- `smt`: proof extraction for any rank across K trees (exists from M3).
- `RoundResult`: adds ticket_tpl (from the drawer input state of the `draw()` transaction) and reserve (output 0 value), so every pool state can be rebuilt from the `draw()` transaction alone (R4).
- Builder policy (S5-5): claims, returns and refreshes spend chain-merged inputs (refresh's idle check depends on the input DAA).
- tn10: `probe claim-m4`: genesis → buy → close → draw → claim (one PAY or FINAL claim) through the public mempool.

## A9. Tests

These follow M3 A8:
- full transactions in the v2.1.0 engine with production flags and committed budgets;
- one change per attack;
- `strike(good, bad, i)`: the named input rejects with a script error and the good transaction passes;
- every attack test ends with the base transaction accepted.

## A10. Out of scope

- Claiming several indices in one transaction, and paying the fee from the prize.
- Ticket transfer.
- Vault shares, requests and the settlement record (M5).
- `refresh()` for the vault, controller, shards and params.
- The real seed, review finding R1 and the missed-draw fallback (parked).

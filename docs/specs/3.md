# M3 spec: `draw()` with a test seed

Status: approved 2026-10-10; implemented in M3 with the changes listed in "Corrections" at the end (see `docs/DECISIONS.md`). The body below is the approved text. Design references are to `docs/design.md` v0.4.1. Interview answers:
- a drawer singleton leads `draw()`;
- the claim deadline is anchored to seed_ref + DRAW_WINDOW;
- the settlement record is deferred to M5;
- F_MIN = 1 KAS;
- the test seed uses a hash mapping;
- A_MAX = 5;
- a pool is created only if its slice > 0;
- the tier split, J-fixing order, cap on total L and witness form are confirmed.

M3 builds:
- `draw()`: winning numbers from a TEST-ONLY seed, the K-leaf count proof, lower-tier budgets and pools, jackpot and second-prize pools, vault settlement, fee payout, caller reward, absorption of expired pools, and fixing J(r+1);
- the delegate legs of the marker, the vault, the controller and the prize pool;
- the genesis additions (vault and drawer);
- the Rust reference and builder.

## A1. Decisions (each becomes a DECISIONS row)

| # | Decision |
|---|---|
| D37 | **Drawer singleton leads `draw()` (deviation from R6, "the frozen marker leads `draw()`").** A new role **0x0A drawer** holds the `draw()` code. Its value is R, posted at genesis and never refunded (as D30). It is spent and recreated with round + 1 by every `draw()`, at input 0. The marker, vault, controller and absorbed pools are delegates. **Why:** `close()` validates the marker output with `validateOutputStateWithTemplate`, so every `close()` carries the marker's full script. A K = 16 `close()` uses 856,824 transient mass with the 756 B placeholder marker (costs M2-a). That leaves about 10.8 kB under 90%, and 16 unrolled verify paths alone are about 16 kB. The marker therefore stays small. |
| D38 | **Route of trust (R5, no hash cycle):** the drawer has the controller template hash as a *constructor constant*. Its *state* holds pool_tpl and vault_tpl. The controller's existing route table gives marker_tpl. The marker, vault and pool have the drawer template hash as a constructor constant. The controller's draw leg authenticates a genuine marker of round r at input 1 (via its own marker_tpl). The marker's leg in turn requires the genuine drawer at input 0, so the controller's state layout and the shard and params legs do not change. Dependency order: controller ← drawer ← {marker, vault, pool}; controller ← {shard, params}. |
| D39 | **Claim deadline (interview):** D_claim = max(own, seed_ref + DRAW_WINDOW) + CLAIM_WINDOW. own is the maximum creation DAA score over all inputs. DRAW_WINDOW = 432,000 DAA (12 h, the seed-validity window of KIP-21, design 11). CLAIM_WINDOW = 6,048,000 DAA (7 days at 10 BPS, DECISIONS D23 source). Winners get at least 7 days after seed_ref + 12 h. Only a `draw()` later than that, the parked missed-draw case, can shorten the window. An honest caller adds a fresh funding input, so own ≈ now. |
| D40 | **No settlement record in M3 (interview).** The vault gets the full design-6 layout now: total_shares, pending deposit assets and pending withdrawal shares are carried unchanged. M5 adds the record and may add one `draw()` output. That is a recorded deviation from the M5 milestone text "keeps `draw()`'s shape fixed". |
| D41 | **Fee (interview):** F_MIN = 1 KAS (100,000,000 sompi). If A + F ≥ F_MIN, `draw()` pays A + F in one plain output to the fee address stored in the **round r+1 controller**, and A' = 0. Otherwise A' = A + F. The marker has no fee address. The accumulator mixes rounds and already lives in that controller, so the fee follows the address in force when it is paid. |
| D42 | **TEST-ONLY seed and its mapping (interview).** The drawer entry is `draw_test_seed(byte[32] test_only_seed, …)`. h = blake2b("KLOT/test-seed" (14 B) ‖ cov (32) ‖ round (8 B LE) ‖ test_only_seed (32)). rank = bin2num(h[0..7] ‖ 0x00) mod 142,506. bonus = bin2num(h[7..14] ‖ 0x00) mod m + 1, with m = the marker's m. Both values are 56-bit non-negative, so the bias is below 2⁻³⁸. The caller supplies the 5 main numbers, and the script checks that they are canonical and that their colex rank (M1 3.1) equals rank. A real seed later replaces only where h comes from. |
| D43 | **Test-seed build gate (milestone criterion).** `covenants/drawer.sil` is compiled only by `lottery::draw`, which is `#[cfg(feature = "test-seed")]`. The `lottery` crate gets two features, `test-seed` (default) and `mainnet`. `lib.rs` has `#[cfg(all(feature = "test-seed", feature = "mainnet"))] compile_error!("TEST-ONLY seed cannot be built for mainnet")`. A mainnet build must use `--no-default-features --features mainnet`, and then no drawer exists. The genesis builder also refuses a drawer for any network other than testnet or devnet. |
| D44 | **A_MAX = 5 (interview):** a `draw()` absorbs 0..5 expired pools of earlier rounds; the caller chooses. M4 re-checks this, because the pool's claim code will make pool inputs larger. |
| D45 | **Pool creation rule (interview).** The jackpot pool exists iff h_J ≥ 1 and J > 0. The second-prize pool exists iff n2 ≥ 1 and G2 > 0. Lower-tier pool t exists iff slice_t = floor(B_t / W_t) ≥ 1. Otherwise its B_t goes to the boost pot. A lower-tier pool holds B_t, including the remainder B_t − W_t·slice_t, which reaches the boost pot at absorption (4.4). |
| D46 | **Tier split confirmed (D18):** (4+b, 4, 3+b, 3, 2+b) = (400, 300, 300, 0, 0) bp, with W = 125, 125(m − 1), 3,000, 3,000(m − 1), 23,000 (4.1). The marker's m and shares are round r's. |
| D47 | **J fixing confirmed (4.6 proposal, DECISIONS 2026-10-09 rows):** base → lower if it fails → boost up to the safe level → top-up. The cap applies to the total liability: L = J_house + G2(m − 1) ≤ floor(V' × cap / 10⁴). Every check uses round r+1's m, price and active shares (the round whose jackpot is fixed), and the immutable e, j, g, margin and cap. |
| D48 | **"Largest value" by witness (interview).** The caller supplies x1, y and x2. The script checks pass at the value and failure at value + 1 (A5). The predicate is monotone, so the witness is unique. This differs from M2's D25, where the non-monotone m choice needed a closed form. |
| D49 | **Drawer instance constants in drawer state (as D17):** pool_tpl, vault_tpl, F_MIN, CLAIM_WINDOW and DRAW_WINDOW are set at genesis and copied unchanged. M_DRAW = 50 is a drawer *template* constant: the largest m it can draw, because the count loop is unrolled. The genesis builder requires the controller's m_max ≤ M_DRAW, and `draw()` requires the marker's m ≤ M_DRAW. Without that, a round could never be drawn (genesis is trusted, review note D). |
| D50 | **Vault in genesis (D31 completed):** the genesis transaction also creates the vault (round 0, total_assets = V₀, total_shares = 0, pending fields 0, liability = L(1)) and the drawer (round 1). The genesis builder requires L(1) ≤ floor(V₀ × cap / 10⁴) and the controller's v_rec = V₀. Dead shares or a virtual offset are set in M5. |
| D51 | **Lock:** `draw()` requires `tx.daa ≥ seed_ref`, the lower bound standing in for "the seed block exists" (7.3). Each absorbed pool also requires `tx.daa ≥` its own deadline, so the builder sets lock_time to the maximum. The open review row R1 (the caller chooses seed_ref) is unchanged. |
| D52 | **Test fixtures (as D33):** M3 tests run real genesis → buys → `close()` → `draw()` in the local engine. For absorption, a second round's `draw()` absorbs the first round's pools with lock_time ≥ their deadline. The local engine does not compare lock_time with block DAA (DECISIONS fact row on check 7). |

## A2. Constants

Drawer template constants:
- ROLE_DRAWER 0x0A, ROLE_POOL 0x04, ROLE_VAULT 0x06, ROLE_MARKER 0x03, ROLE_CONTROLLER 0x01;
- K_MAX 16, M_DRAW 50, A_MAX 5, F_MAX 8, N 142,506, DEPTH 18;
- TOTAL_MAX 2⁶², DAA_MAX 5·10¹¹, BP 10⁴, the seed domain tag;
- CONTROLLER_TPL (constructor constant).

Marker, vault and pool: DRAWER_TPL (constructor constant).

Tier codes: 0 jackpot, 1 second prize, 2..6 the lower slots (4+b, 4, 3+b, 3, 2+b).

## A3. State layouts (field order = byte order; int = 8-byte payload)

**A3.1 Drawer (0x0A).** Value: R. Fields:
- role;
- round (the round this drawer draws next);
- pool_tpl byte[32];
- vault_tpl byte[32];
- f_min;
- claim_window;
- draw_window.

**A3.2 Vault (0x06).** Value: total_assets + pend_dep + R. Fields:
- role;
- round (the last drawn round);
- total_assets;
- total_shares;
- pend_dep;
- pend_wsh;
- liability.

**A3.3 Pool (0x04).** Value: remaining + R. Fields:
- role;
- round;
- tier byte;
- slice (J, G2 or slice_t);
- win byte[6] (n1..n5, bonus);
- m;
- k;
- roots byte[512] (as the marker);
- deadline;
- funder_class byte;
- funder_key byte[33].

The pool's entries are `absorb_leg(int drawer_pl, int drawer_sl)` and `claim()`. `claim()` is an always-rejecting placeholder until M4 (as D13).

**A3.4 Marker (0x03):** the M2 layout is unchanged. Its code gets `draw_leg(int drawer_pl, int drawer_sl)` and the constructor constant DRAWER_TPL, replacing the D28 placeholder.

**A3.5 Controller (0x01):** the layout is unchanged. Its code gets `draw_leg(int marker_pl, int marker_sl)`. The new controller template hash changes the shard and params constants. The close K = 16 measurement is repeated (M3-f).

**Ranges (R8), checked by the drawer:**
- drawer: role = 0x0A; 1 ≤ round < TOTAL_MAX; 0 ≤ f_min ≤ 10¹⁰; 0 ≤ claim_window, draw_window < DAA_MAX;
- vault: total_assets, total_shares, pend_dep, pend_wsh and liability in [0, TOTAL_MAX];
- every pool read as an absorbed input: remaining = value − R ≥ 0.

The controller and marker fields are re-checked against the M2 A3 ranges the drawer uses (m ≤ M_DRAW, 1 ≤ k ≤ K_MAX, the shares).

## A4. `draw()` (drawer entry `draw_test_seed`; leader)

**Shape:**

| | Index | Object |
|---|---|---|
| Input | 0 | drawer (round r) |
| Input | 1 | marker r |
| Input | 2 | vault (round r − 1) |
| Input | 3 | controller r + 1 (drawn = 0) |
| Input | 4..3+a | absorbed pools, 0 ≤ a ≤ A_MAX |
| Input | 4+a.. | caller funding, 1..F_MAX inputs, zero ID |
| Output | 0 | drawer' (round r + 1) |
| Output | 1 | vault' |
| Output | 2 | controller' (drawn = 1) |
| Output | 3..2+np | the new pools, in tier order 0..6, only those that exist (D45) |
| Output | 3+np | fee output, only if A + F ≥ f_min |
| Output | next | marker reserve refund (R to the marker's funder) |
| Output | next a | absorbed pool refund i (R to pool i's funder), in input order |
| Output | last | caller output, zero ID |

Output count = 3 + np + fee + 1 + a + 1.

**Arguments:**
- test_only_seed byte[32];
- win5 byte[5];
- leaves (2m·k bytes: each shard's counts at the winning rank) and siblings (576·k bytes);
- x1, y, x2 (the A5 witnesses);
- ctrl_pl, ctrl_sl, marker_pl, marker_sl, vault_pl, vault_sl, pool_pl, pool_sl (input template lengths);
- pool_prefix and pool_suffix (new pools, checked against pool_tpl);
- funder_class and funder_key[33] (the new pools' reserve funder).

**Checks, in order (test IDs cite these numbers):**
1. activeInputIndex = 0; cov = OpInputCovenantId(0). Own state ranges (A3.1). Argument lengths in [0, 1,000,000].
2. OpCovInputCount(cov) = 4 + a with 0 ≤ a ≤ A_MAX. Inputs 1..3+a have ID cov; inputs ≥ 4 + a have the zero ID, 1 ≤ n_fund ≤ F_MAX.
3. ctrl = readInputStateWithTemplate(3, …, CONTROLLER_TPL): role 0x01, round = r + 1, drawn = 0, M2 A3 ranges for the fields used, m ≤ M_DRAW.
4. mk = readInputStateWithTemplate(1, …, ctrl.marker_tpl): role 0x03, round = r, k = ctrl.k, 2 ≤ mk.m ≤ M_DRAW, M2 A3 share ranges, 0 ≤ P_R ≤ S ≤ TOTAL_MAX, 0 ≤ j_boost ≤ jackpot ≤ TOTAL_MAX, 0 ≤ g2 ≤ TOTAL_MAX. Input 1 value = S − P_R − C_close + j_boost + R, with C_close = muldiv(S, s_c) and R = ctrl.reserve.
5. vt = readInputStateWithTemplate(2, …, vault_tpl): role 0x06, round = r − 1, A3.2 ranges. Input 2 value = total_assets + pend_dep + R.
6. Input 0 value = R. Input 3 value = O + acc + R with O ≥ 0.
7. `tx.daa ≥ mk.seed_ref` (D51).
8. **Seed (D42):** compute h, rank and bonus. win5 is canonical (M1 3.1), and its colex rank equals rank.
9. **Leaves:** leaves.length = 2·mk.m·k and siblings.length = 576·k. For each i < k:
   - counts_i = leaves[2m·i .. 2m(i + 1)];
   - leaf_i = Z_0 if counts_i is all zero, else H(0x00 ‖ rank (3 B) ‖ counts_i);
   - walking leaf_i up 18 levels with siblings[576·i ..] reaches mk.roots[32i .. 32i + 32].
10. **Counts:** each 2-byte count is in [0, 32,767]. h_J = Σ_i count_i[bonus]. n2 = #{b ∈ 1..m, b ≠ bonus : Σ_i count_i[b] ≥ 1}. The loops are bounded by K_MAX and M_DRAW.
11. **Round amounts (5.1), marker shares:**
    - s_H = 10⁴ − s_f − s_r − s_c − s_d − Σst ≥ 0;
    - F, C_draw, B_1..5 and H = muldiv(S, share);
    - b_r = S − P_R − F − C_close − C_draw − ΣB − H ≥ 0.
12. **Pools (D45):**
    - J = mk.jackpot, J_house = J − mk.j_boost, G2 = mk.g2;
    - jp = [h_J ≥ 1 ∧ J > 0], sp = [n2 ≥ 1 ∧ G2 > 0];
    - slice_t = B_t / W_t with W_t from mk.m (A6 bounds), and lp_t = [slice_t ≥ 1];
    - np = jp + sp + Σ lp_t.
13. **Covenant outputs (R2):** OpAuthOutputCount(0) = 3 + np; OpAuthOutputIdx(0, j) = j for j < 3 + np; OpCovOutputCount(cov) = 3 + np.
14. **Vault settlement (5.4):** V' = total_assets + H − J_house·jp − G2·n2·sp ≥ 0, with each step guarded (A6).
15. **Boost pot (5.5):**
    - ΣQ = Σ over absorbed pools of (value − R);
    - O' = O + b_r + mk.j_boost·(1 − jp) + ΣB_t·(1 − lp_t) + ΣQ.
    Lower-tier money and unheld J_boost go to the pot, never to the vault.
16. **Fee (D41):** T_F = acc + F. paid = [T_F ≥ f_min]; A' = paid ? 0 : T_F.
17. **Fix J(r+1) (A5):** from V', O' and ctrl. Gives J' = x2 + y, J_boost' = y, G2' = muldiv(J', g) and L' = x2 + G2'·(ctrl.m − 1).
18. **Absorbed pools:** for each i < a:
    - pl_i = readInputStateWithTemplate(4 + i, …, pool_tpl): role 0x04, pl_i.round < r, A3 ranges;
    - tx.daa ≥ pl_i.deadline (lower-bound lock; the pool leg also checks it);
    - funder class per D11.
19. own = max over inputs of OpTxInputDaaScore, with own < DAA_MAX. D_claim = max(own, mk.seed_ref + draw_window) + claim_window < DAA_MAX.
20. **Output values (R7):**
    - out0 = R;
    - out1 = V' + pend_dep + R;
    - out2 = O' + A' + R;
    - the pools: J (jackpot), n2·G2 (second prize) or B_t, each + R;
    - fee = T_F;
    - each refund = R;
    - output count = 3 + np + paid + 1 + a + 1.
21. **Plain outputs (R7):** every output ≥ 3 + np has the zero ID. The fee scriptPubKey is rebuilt from ctrl.fee_class and fee_key. The marker refund script is rebuilt from mk.funder, and each pool refund from pl_i.funder (D11 forms, as buy check 15).
22. validateOutputStateWithInputTemplate(0, drawer with round + 1, all else unchanged).
23. validateOutputStateWithInputTemplate(1, vault with round = r, total_assets = V', liability = L', and shares and pending fields unchanged).
24. validateOutputStateWithInputTemplate(2, controller r+1 with jackpot = J', j_boost = y, g2 = G2', liability = L', v_rec = V', acc = A', drawn = 1, and every other field unchanged).
25. funder_class and padding per D11. For each new pool p: validateOutputStateWithTemplate(3 + p, pool {round r, tier, slice, win = win5 ‖ bonus, mk.m, k, mk.roots, D_claim, funder}, pool_prefix, pool_suffix, pool_tpl).

**Delegate legs (R6):**
- **Marker `draw_leg`:**
  - L1: activeInputIndex = 1;
  - L2: OpInputCovenantId(0) = own ID;
  - L3: OpAuthOutputCount(1) = 0;
  - L4: readInputStateWithTemplate(0, …, DRAWER_TPL) has role 0x0A and round = own round.
- **Vault `draw_leg`:** L1 index = 2; L2, L3 as above; L4 the drawer's round = own round + 1.
- **Controller `draw_leg`:**
  - L1: index = 3; L2, L3 as above;
  - L4: readInputStateWithTemplate(1, …, marker_tpl) has role 0x03 and round = own round − 1;
  - L5: own drawn = 0.
  The genuine marker's own leg authenticates the drawer (D38).
- **Pool `absorb_leg`:**
  - L1: index ≥ 4; L2, L3 as above;
  - L4: drawer genuine with round > own round;
  - L5: `tx.daa ≥ deadline`.
- The vault has no other entry in M3. The marker's only entry is `draw_leg`.

**Conservation (5.5, economic value, excluding R):**
- marker (S − P_R − C_close + J_boost) + vault V + controller (O + A) + ΣQ
- = pools (J·jp + n2·G2·sp + Σ B_t·lp_t) + vault' V' + controller' (O' + A') + fee (T_F·paid) + C_draw.

The caller output = funding − np·R + C_draw − fee. It is not checked in script: every other output is exact, so the caller output is the remainder, as in D29. Refunds are separate outputs, even when the funder is the caller. Reserves:
- the drawer, vault and controller R move with their objects;
- the marker R and each absorbed pool's R go to their funders;
- the caller posts np new pool reserves.

## A5. Fixing J(r+1) (4.6, D47, D48)

Let:
- m' = ctrl.m and p = ctrl.price;
- s_H' and w' from ctrl's active shares (as M2 check 17/18);
- a = muldiv(p·s_H', 10⁴ − e) / 10⁴ and q = p·w' / margin;
- E = a·N·m', W = q·N·m', Cv = muldiv(V', cap).

**pass(x, y)**, evaluated without overflow:
1. false if x > E, x > Cv or y > W − x;
2. otherwise G = muldiv(x + y, g), and pass ⇔ G ≤ (E − x)/(m' − 1), G ≤ (W − x − y)/(m' − 1) and G ≤ (Cv − x)/(m' − 1).

This is exactly:
- edge: x + G(m' − 1) ≤ E;
- whale: x + y + G(m' − 1) ≤ W;
- cap: x + G(m' − 1) ≤ Cv.

pass is monotone (non-increasing in x and in y), and pass(0, 0) holds.

**Witness checks:**
1. x_b = muldiv(V', j). If pass(x_b, 0), require x1 = x_b. Otherwise require 0 ≤ x1 < x_b, pass(x1, 0) and ¬pass(x1 + 1, 0).
2. Require 0 ≤ y ≤ O', pass(x1, y), and y = O' or ¬pass(x1, y + 1).
3. Require x2 ≥ x1, pass(x2, y) and ¬pass(x2 + 1, y).

`game::fix_jackpot` computes the same values by bisection and is tested against brute force (DP17).

## A6. Arithmetic (R8)

- muldiv as M2 A6.
- Every addition a + b of money is preceded by a ≤ TOTAL_MAX − b:
  - V + H;
  - each O' term;
  - pool amount + R;
  - T_F;
  - V' + pend_dep + R;
  - O' + A' + R.
  These can fail only beyond the money supply, and the engine's OpAdd is checked (review note C).
- W_t ≤ 3,000 · 254 < 10⁶. n2·G2: n2 ≤ 254 and G2 ≤ TOTAL_MAX/254 is checked first. Counts sum over ≤ 16 shards ≤ 524,272.
- E, W ≤ 3.6·10¹⁸ (M2 A6); x + y ≤ W inside pass; G2'·(m' − 1) ≤ Cv − x2 holds by pass.
- Seed integers: two 56-bit values; mod by N and by m ≥ 2.
- D_claim: own < DAA_MAX and seed_ref + draw_window guarded below DAA_MAX before adding claim_window.

## A9. Round result record (design 6, 9)

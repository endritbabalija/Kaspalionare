# M2 spec: `close()`, game-size rule and admin parameters

Status: approved 2026-10-10; implemented in M2 with the corrections marked "(corrected)" and listed in "Corrections" at the end (see `docs/DECISIONS.md`).

Approved 2026-10-10 (plan `2-mighty-blum`). Interview answers: separate parameter UTXO (K3); tier split 400/300/300 bp over 4+b, 4 and 3+b; s_C = s_D = 50 bp; m in [2, 50]; margin 11,700 bp; cap 2,000 bp; 24 h rounds with D_min 2 h; the late-close gap accepted and documented; if K = 16 does not fit, keep K = 16 and lower B_MAX; whale-check form confirmed.

## A1. Decisions (each becomes a DECISIONS row)

| # | Decision |
|---|---|
| D16 | **Parameter UTXO (K3; deviation from the 5.6 proposal).** A new role **0x09 params** holds the admin key hash, the nonce, the used-this-round flag and the *next-round* values (s_F, s_R, fee address). `set_params()` spends only this UTXO, whose value is R and which holds no money. `close()` spends it as a delegate, copies the next-round values into round r+1's controller, and recreates it with the round number advanced and the flag cleared. The admin has no spend path on any value-holding UTXO. |
| D17 | **Instance parameters are immutable controller state.** They are set at genesis and copied unchanged by every `close()`: K, price, d, R, s_C, s_D, s_t[5], e, j, g, margin, m_min, m_max, cap, ROUND_LEN, D_MIN and SEED_OFFSET. The admin-adjustable s_F, s_R and fee address are the *active* fields. Tests can vary parameters without recompiling, and the launch bundle shows them. |
| D18 | **Lower tiers:** s_t slots in the fixed order (4+b, 4, 3+b, 3, 2+b) = (400, 300, 300, 0, 0) bp. Tiers with 0 do not pay. M3 confirms the split without a layout change. |
| D19 | **s_C = 50, s_D = 50 bp.** Open liveness note: below about S = 100 KAS, C_close does not cover a priority fee of about 0.5 KAS (measured in M2-d). |
| D20 | **m_min = 2, m_max = 50**, provisional; M3 and M6 re-measure. Range check m_max ≤ M_HARD = 255 (the shard limit). |
| D21 | **Margin = 11,700 bp.** The whale-check form is confirmed: C·p·(1 − Σs_t − s_R − s_C − s_D) ≥ margin·(J + G2(m − 1)). Other players' lower-tier money stays an open item. |
| D22 | **Cap = 2,000 bp** (used by `draw()` in M3). |
| D23 | **ROUND_LEN = 864,000 and D_MIN = 72,000 DAA** (24 h and 2 h at 10 BPS: mainnet and testnet-10 both use `BlockrateParams::new::<10>()`, `consensus/core/src/config/params.rs:643,699`). **SEED_OFFSET = 600** is a placeholder while randomness is parked. |
| D24 | **Late-close gap (accepted; deviates from 7.2's "always").** No script can bound the current DAA from above. A very late `close()` whose caller uses only old inputs can therefore set T(r+1) below the DAA of the block that includes it. That round's shards then sell nothing. No money moves wrongly, and the next `close()` opens a normal round. Honest callers add a fresh funding input. |
| D25 | **m(r+1) is computed in closed form (revised 2026-10-10 after Stage 1; the witness form was not unique when the boost dominates).** Each check has the form c ≤ s·x, with c = base − Ĝ2 and s = slope − Ĝ2 (base Ĵ_house and slope a·N for the edge rule; base Ĵ and slope q·N for the whale check). Its passing set in x ≥ 1 is then an interval: s > 0: x ≥ ceil(c / s) (all x if c ≤ 0); s = 0: all x if c ≤ 0, else none; s < 0: none if c > 0, else x ≤ floor((−c) / (−s)). Every division has non-negative operands, selected by branching. The script intersects both intervals with [m_min, m_max] and computes m' = the lower end if the intersection is non-empty, else m_max. It requires the argument m_next = m'. The argument is kept so that the output-state check can bind it. The Rust reference brute-forces it over every m (CP9). |
| D26 | **The Ĵ estimate saturates** at SAT = 10¹⁷ sompi for (V_rec + H_r) and for the boost estimate. It affects only the choice of m: `draw()` re-checks everything (4.6). It keeps every product within 64 bits (A6). |
| D27 | **Controller authorizes every covenant output of `close()`.** Shards and params are delegates. Each authenticates the leader through `readInputStateWithTemplate(0, …, controllerTemplateHash)` with the controller template hash as a *constructor constant* of the shard and params templates. The controller holds the route table (shard, marker and params template hashes) in *state*, so no template depends on itself. |
| D28 | **The marker template is an M2 placeholder** (as D13): the state layout of A3.3 and one always-rejecting entry. M3 replaces the code, and its new hash goes into the route table at genesis. |
| D29 | **`close()` shape policy** (the D2 analogue): caller funding 1..F_MAX inputs with the zero ID; exactly one caller output, last, with the zero ID. The caller posts the marker's R and pays the fee, and C_close lands in the caller output. |
| D30 | **The controller has no reserve-funder field** (deviation from the design 6 table). The controller reserve is posted at genesis and never refunded. |
| D31 | **Genesis (off-chain builder):** one transaction creates the controller (round 1, drawn = 1, J(1), J_boost(1), G2(1), L(1) and V_rec from deployment inputs), the params and K shards under a fresh KIP-20 covenant ID. The vault joins genesis in M3/M5. |
| D32 | **K target 16.** If a K = 16 `close()` exceeds 90% of any per-transaction mass, B_MAX drops to 4 and the measurement is repeated (interview). (corrected: applied, B_MAX = 4; storage is fixed by R = 1.69 KAS, not by B_MAX) |
| D33 | **Test fixtures:** until M3, a "drawn" round r+1 controller is fabricated directly as a UTXO (drawn = 1, J fields set), as D14 did for shards. The late buy against an old shard is shown with a small test ledger that rejects spent outpoints: the cut-off is structural, not a script check. |
| D34 | **Admin nonce:** strictly greater than the stored nonce, gaps allowed. Message = `"KLOT/set_params"` (15 B) ‖ cov (32) ‖ target round = round + 1 (8 B LE) ‖ s_F (8) ‖ s_R (8) ‖ fee_class (1) ‖ fee_key (33) ‖ nonce (8). It is signed as a Schnorr signature over blake2b(message) and verified with `checkMsgSig` (OpCheckSigFromStack, `opcodes/mod.rs:1438`). The key is stored as blake2b(32-byte x-only pubkey). |
| D35 | **V_rec and A are carried unchanged by `close()`.** J(r+1), J_boost, G2 and L(r+1) start at 0 and are written by `draw()` of round r (M3). |

## A4. `close()` (controller entry; leader)

**Shape:**

| | Index | Object |
|---|---|---|
| Input | 0 | controller r |
| Input | 1 | params (round r) |
| Input | 2..k+1 | shard i at 2 + i |
| Input | k+2.. | caller funding, 1..F_MAX inputs, zero ID |
| Output | 0 | controller r+1 |
| Output | 1 | params' |
| Output | 2..k+1 | new shard i |
| Output | k+2 | marker r |
| Output | k+3 | caller output, zero ID |

Exactly k + 4 outputs.

**Arguments:**
- m_next;
- funder_class and funder_key[33] (the marker reserve funder);
- shard_pl, shard_sl, params_pl and params_sl (template lengths, bound by the hashes);
- marker_prefix and marker_suffix (checked against marker_tpl).

**Checks, in order (test IDs cite these numbers):**
1. activeInputIndex = 0; cov = OpInputCovenantId(0).
2. Own state ranges (A3), plus the share room Σst + s_c + s_d + S_F_CAP + S_R_CAP ≤ 10⁴ (corrected: review finding R2) and the extra range checks listed in "Corrections".
3. nIn = k + 2 + n with 1 ≤ n ≤ F_MAX; inputs ≥ k + 2 have the zero ID.
4. OpCovInputCount(cov) = k + 2.
5. OpAuthOutputCount(0) = k + 3; OpAuthOutputIdx(0, j) = j for j ≤ k + 2; OpCovOutputCount(cov) = k + 3.
6. Outputs = k + 4; output k + 3 has the zero ID.
7. `tx.daa ≥ T` (lower-bound lock).
8. drawn = 1.
9. params = readInputStateWithTemplate(1, …, params_tpl): role 0x09, round = r, next_s_f ≤ S_F_CAP, next_s_r ≤ S_R_CAP (corrected: also next_s_f, next_s_r ≥ 0).
10. For each i < k: shard = readInputStateWithTemplate(2 + i, …, shard_tpl), with:
    - role 0x02, round = r, shard_index = i;
    - m, price, d, s_r and T equal the controller's;
    - 0 ≤ P_R,i ≤ S_i ≤ TOTAL_MAX − ΣS so far;
    - input value = S_i − P_R,i + R.

    Sum S and P_R; collect the roots.
11. s_H = 10⁴ − s_f − s_r − s_c − s_d − Σst ≥ 0. F, C_close, C_draw, B_1..5 and H = muldiv(S, share). b_r = S − P_R − F − C_close − C_draw − ΣB − H ≥ 0.
12. V_c = value(0); O = V_c − acc − R; 0 ≤ j_boost ≤ O.
13. out0 = V_c − j_boost.
14. value(1) = R and out1 = R.
15. out(2 + i) = R (corrected: checked inside the check 23 loop).
16. out(k + 2) = S − P_R − C_close + j_boost + R.
17. Next shares: s_f' = next_s_f, s_r' = next_s_r; s_H' = 10⁴ − s_f' − s_r' − s_c − s_d − Σst ≥ 0.
18. Ĵ_house = muldiv(min(V_rec + H, SAT), j); Ĵ_boost = min(O − j_boost + b_r, SAT); Ĵ = Ĵ_house + Ĵ_boost; Ĝ2 = muldiv(Ĵ, g); a = muldiv(price·s_H', 10⁴ − e) / 10⁴; q = price·w' / margin, with w' = 10⁴ − Σst − s_r' − s_c − s_d. pass(x) ⇔ Ĵ_house + Ĝ2(x − 1) ≤ a·N·x and Ĵ + Ĝ2(x − 1) ≤ q·N·x.
19. m_next = the D25 closed form (unique).
20. own = max over all inputs of OpTxInputDaaScore (corrected: own < DAA_MAX is required first; the caller choosing own through its funding inputs is the OPEN review finding R1); T' = max(T + round_len, own + d_min) < DAA_MAX; seed_ref = own + seed_offset.
21. validateOutputState(0, controller r+1):
    - round + 1; m = m_next; deadline T';
    - s_f', s_r' and the fee address from params;
    - jackpot = j_boost = g2 = liability = 0; drawn = 0;
    - v_rec, acc, the route table and every immutable unchanged.
22. validateOutputStateWithInputTemplate(1, params' with round + 1 and used = 0, all else unchanged).
23. validateOutputStateWithInputTemplate(2 + i, shard with round + 1, index i, m_next, price, d, s_r', T', root Z_18, S = 0, P_R = 0).
24. funder_class ∈ {0, 1, 2} with the D11 padding rule. validateOutputStateWithTemplate(k + 2, marker r, marker_prefix, marker_suffix, marker_tpl), with:
    - k, the roots, S and P_R;
    - the controller's m, jackpot, j_boost and g2;
    - the active s_f, s_r, s_c, s_d and st;
    - seed_ref and the funder.

**Delegate legs:**
- `close_leg` on the shard: L1 activeInputIndex ≥ 2; L2 OpInputCovenantId(0) = own ID; L3 OpAuthOutputCount(self) = 0; L4 readInputStateWithTemplate(0, ctrl_pl, ctrl_sl, controllerTemplateHash) has role 0x01 and round = own round; L5 OpCovInputCount(cov) = ctrl.k + 2 (corrected: written as OpCovInputCount(cov) − 2 = ctrl.k).
- `close_leg` on the params: the same, with activeInputIndex = 1.

**Conservation (5.5, economic value, excluding R).** Controller (O + A) → controller' (O − J_boost + A) + marker (S − P_R − C_close + J_boost). Shards (S − P_R) → new shards (0). Caller output = funding − R(marker) − fee + C_close. Reserves move with the objects: K + 2 in, K + 2 out, plus the marker R posted by the caller. No refund.

## A5. `set_params()` (params entry)

**Shape:**
- input 0 is the params; inputs 1..n are admin funding (zero ID, 1 ≤ n ≤ F_MAX);
- output 0 is the params successor; output 1 is optional change (zero ID) (corrected: the script requires 1 or 2 outputs);
- OpCovInputCount = 1, OpAuthOutputCount(0) = 1, OpAuthOutputIdx(0, 0) = 0, OpCovOutputCount = 1.

**Arguments:** s_f, s_r, fee_class, fee_key[33], nonce, admin_pk (pubkey), sig (datasig) (corrected: named `new_nonce` and `admin_sig`; `sig` is a reserved type name).

**Checks:**
1. The shape above.
2. used = 0.
3. 0 ≤ s_f ≤ 1,000; 0 ≤ s_r ≤ 1,500; the fee script class and padding follow D11.
4. stored nonce < nonce < 2⁶².
5. blake2b(admin_pk) = admin_hash.
6. checkMsgSig(sig, blake2b(msg D34), admin_pk), with target round = round + 1.
7. out0 value = in0 value.
8. validateOutputState(0, params with nonce, used = 1 and next_* = the arguments, all else unchanged).

## A6. Arithmetic (R8)

- **muldiv(x, s)** = (x / 10⁴)·s + ((x % 10⁴)·s) / 10⁴. It is exact for 0 ≤ x ≤ 2⁶² and 0 ≤ s ≤ 10⁴, and its maximum is 4.6·10¹⁸.
- **Bounds:**
  - a·N·x ≤ 10¹¹ · 142,506 · 255 ≈ 3.6·10¹⁸;
  - q ≤ price, so q·N·x is bounded the same way;
  - Ĵ ≤ 5·10¹⁶ + 10¹⁷;
  - Ĝ2 ≤ 1.5·10¹⁶;
  - Ĵ + Ĝ2·254 ≤ 4·10¹⁸;
  - price·s_H' ≤ 10¹⁵; price·w' ≤ 10¹⁵;
  - min(V_rec + H, SAT) is evaluated as SAT when V_rec ≥ SAT, so the sum never overflows.
- **Rounding:** a equals the design's floor(p(10⁴ − e)s_H / 10⁸) exactly (nested floors). q rounds down, which favours the whale check.
- The Rust reference `lottery::game` mirrors every step bit for bit.

5. CA1–CA4 fail as specified, including the late buy on an old shard. A late close still opens a round that sells (CP6).
6. SA1–SA12 fail as specified.

8. M2-a…M2-d are recorded in `docs/costs.md` and M2-e in `docs/tn10-mass-check.md`. The full `cargo test` passes, M0 and M1 included. The covenant-reviewer has run. Rows D16–D35 are in DECISIONS.

## Corrections (implementation, 2026-10-10)

Each is a row in `docs/DECISIONS.md`.

- D25 is the closed form (revised after Stage 1; the witness form was not unique). D36: saturation is evaluated as SAT if a ≥ SAT, else min(a + b, SAT).
- D32 applied: B_MAX = 4. R = 1.69 KAS from R = 4C(K + 3)/(0.9 L) (M2-c), with the `close()` caller output ≥ 1 KAS as a builder policy (`close::MIN_CALLER_OUTPUT`), not a script check. Test fixtures use R = 1.69, not 1.44.
- Check 2 also requires: the share room Σst + s_c + s_d + S_F_CAP + S_R_CAP ≤ 10⁴ (review finding R2); role = 0x01; round < TOTAL_MAX; s_c, s_d, st_i ≤ 10⁴; the template-length arguments in [0, 1,000,000]. The genesis builder refuses instances outside A3 or the share room.
- Check 9 also requires next_s_f, next_s_r ≥ 0. Check 20 requires own < DAA_MAX first.
- Check 15 is inside the check 23 loop, so it runs after check 16.
